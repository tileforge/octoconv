WHAT THESE TWO SHOW
-------------------

1. Both end in `error: the XeTeX engine had an unrecoverable error`, which
   isTectonicTerminal already matches -- so a missing package is ALREADY
   classified terminal today. What it is not is DIAGNOSABLE: the client is
   told "the document could not be typeset" and has to guess which
   \usepackage to remove. That gap is precisely 64-03's content.

2. The package name is present, in LaTeX's own wording, on its own line:

       ! LaTeX Error: File `pgfplots.sty' not found.

   A file name, not a package name -- `pgfplots.sty` -> `pgfplots`. Any
   parser 64-03 writes must be tested against THIS string.

3. A third document (missingpkg.tex, \usepackage{tikz}) compiled CLEANLY to
   a 2.5 KiB PDF. tikz is in the declared set, so it must -- and it is the
   negative control that keeps row 2 from being "the engine fails on any
   \usepackage".

4. Fontconfig prints `Cannot load default config file: No such file: (null)`
   on every run, including the successful one. It is noise, not a failure,
   and a parser that treats any line containing "error" as the cause would
   report it.
