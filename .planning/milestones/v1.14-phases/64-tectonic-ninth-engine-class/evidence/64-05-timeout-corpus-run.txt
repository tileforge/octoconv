recommendation:
  TECTONIC_ENGINE_TIMEOUT = ceil(worst s/pass x pass ceiling x margin)
                          = ceil(6.313 x 7 x 1.5)

  pass ceiling 7: the ENGINE's own maximum, not a corpus statistic.
  Tectonic reruns until its references converge and then stops, saying
  'stopping at 6 passes' -- seven TeX invocations is the most any
  document can cost, whatever it contains. This is why the derivation
  is not a p95: a percentile here would measure the corpus's mix of
  1-pass and 7-pass documents, which is a property of the corpus.

  margin 1.5: the operator's parameter. It covers the gap between
  this host and the deployment, and the worker's own S3 download and
  upload, which sit inside the same clock but outside this measurement.

  reconciler cap: RECONCILER_ACTIVE_STALE_AFTER = 900s.
  67s clears it: yes (margin 92.6%).
  A value at or above the cap would have the reconciler re-enqueue jobs
  that are still running. If a future corpus pushes the derivation past
  it, the lever is a bound on the INPUT -- the Path-B move OCR made --
  never a smaller margin.

  This is a recommendation, not a decision.
