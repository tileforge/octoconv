<objective>
Build the reduced bundle and make "which LaTeX packages does OctoConv support" a
closed, declared, mechanically-held list.

The bundle decision was locked before planning (64-CONTEXT.md, TECTONIC.md): the
full TeXLive bundle is ~2.69 GiB on a layer, and runtime egress was rejected
because it lets a client's `\usepackage` decide what gets downloaded. What is
left is this plan: build the reduced bundle, and hold the list equal to it.

Output: a build script, a manifest, a Go list, a document, and one test that
fails when any two of those three disagree.
</objective>

## Task 1 — the package set in Go, as the single source of truth

Create `internal/convert/texpackages.go` declaring the set from 64-CONTEXT.md
D-01, grouped and commented by what each group is for:

- **Math** — `amsmath`, `amssymb`, `amsthm`
- **Graphics and colour** — `graphicx`, `xcolor`, `colortbl`
- **Layout and styling** — `geometry`, `titlesec`, `fancyhdr`, `enumitem`,
  `caption`, `booktabs`, `tcolorbox`
- **Links** — `hyperref`
- **Code** — `listings`
- **Language** — `babel`
- **Bibliography** — `biblatex` (backend=bibtex), `natbib`

Plus the **floor**: whatever `article`/`report` requires to compile at all.
**Determine the floor by building, not by listing it here** — Task 2's first
successful compile is what tells you, and the list records the answer with a
comment saying it was measured.

Follow `AllThreatClasses()`'s shape exactly: a package-level slice, an `All()`
returning a fresh copy so callers cannot mutate the vocabulary, and a
`Supports(pkg string) bool`. This is the accessor BOTH gates in 64-03 use; a
second copy of the list anywhere is a plan failure.

Colour and styling are in the set because the operator asked for them by name.
Record that in the file, not just in CONTEXT — a future reader trimming the list
for bundle size should see that these were requested, not assumed.

**Verify:** `All()` returns a copy (mutating the result does not affect a second
call); `Supports` is case-insensitive only if `NormalizeFormat`'s precedent says
so — otherwise exact, and the test says which and why.

## Task 2 — the build script, and the floor it discovers

Create `scripts/tectonic-bundle-build.sh` following
`scripts/probe-timeout-measure.sh`'s shape (bounded, streams progress, prints
its own derivation, fails loudly rather than silently producing a partial
result):

1. Fetch the pinned TeXLive tarball (version pinned in the script, SHA verified).
2. Run `tectonic-texlive-bundles`' `select` with a content list derived from the
   Go set, then `pack` to a `.ttb`.
3. **Emit `deploy/tectonic-bundle/MANIFEST.txt`** — one package name per line,
   sorted, of what actually ended up in the bundle. This is the file Task 4's
   test compares against, so it must be produced BY the build rather than
   written by hand.
4. Print the resulting `.ttb` size and its SHA-256.

**The floor is discovered here.** `select` pulls dependencies; the manifest will
contain more than the Go list asks for. That difference is exactly the floor
plus each package's own dependencies, and Task 4 has to decide what to do about
it — see there.

**Verify:** the script runs end to end and produces a `.ttb` plus a manifest.
Record the run's output under the phase's `evidence/`.

## Task 3 — measure what tikz costs

Run the build twice: once with `tcolorbox` (and therefore `pgf`/`tikz`) in the
set, once without. Record both `.ttb` sizes in
`deploy/tectonic-bundle/PROVENANCE.md`, with the date, the TeXLive version, and
the command.

64-CONTEXT.md D-01 includes `tcolorbox` on an argument ("a document set
described as needing colours and styling that cannot draw a box would generate a
TEX-06 request in its first week") and explicitly promises the cost as a number
rather than an assertion. This task is that promise.

**If the delta is large enough to change the decision, say so and stop** — that
is a Rule 4 deviation (architectural), not something to absorb.

**Verify:** PROVENANCE.md carries two sizes, a date, and the exact commands.

## Task 4 — the test that holds three things equal

`internal/convert/texpackages_test.go`:

**The three-way equality.** The Go list, `MANIFEST.txt`, and
`docs/TYPESETTING.md`'s table must agree. Model it on
`internal/errcode/doc_sync_test.go` — which already does exactly this for the
error-code vocabulary, including the line-anchored table parser and the
`diffSets` helper that names the offending entry rather than reporting a count.

**The direction that matters, and the wrinkle Task 2 creates.** A bundle
manifest legitimately contains transitive dependencies the Go list never names.
So the equality is NOT set equality against the raw manifest. It is:

- every package in the Go list **must** appear in the manifest — a package we
  advertise and did not ship is a document accepted and then failed;
- every package in `docs/TYPESETTING.md`'s table **must** equal the Go list
  exactly, both directions;
- the manifest may contain more, and the test states in its failure message that
  this is expected and why, so a future reader does not "fix" it into strict
  equality.

**Why the manifest and not just the doc.** A doc-sync test proves the list
matches what we *wrote down*. It cannot notice that what we *shipped* is
different — and that is the failure with teeth: a package in the list, absent
from the bundle, is a document the API admits and the worker fails, for a
package we told the client we support.

**Inversion (D-06):** delete one package from the Go list while leaving it in
the doc → the doc-equality half fails naming that package. Add one to the Go list
that the bundle does not contain → the manifest half fails naming it. Run both,
record the output.

## Task 5 — publish the artifact, pinned by a locally computed digest

Upload the `.ttb` as a GitHub Release asset of this repository. Record in
PROVENANCE.md: the release tag, the asset name, the SHA-256, and the date it was
computed.

**The digest is computed locally from the file we built** — never copied from a
published checksum page. `Dockerfile.pandoc-worker`'s own comment states that
rule for a third-party tarball; it applies at least as strongly to an artifact
we publish ourselves, where the temptation to trust it is greater.

**Verify:** `sha256sum` of the downloaded asset equals the recorded digest.
Record the check.

## Task 6 — the document

`docs/TYPESETTING.md`, following `docs/SANITIZE.md`'s shape — a scope section
before the tables, because a client needs to know the boundary before reading
the list:

- the supported package table (held equal to Go by Task 4);
- **what is deliberately unavailable and why**: biber-backed biblatex styles
  (D-07 — no biber binary in the image, and the security reason), custom fonts
  and `fontspec` (TEX-07, deferred);
- how to request an extension (TEX-06's procedure, in outline — this phase ships
  the preconditions, not the workflow).

Absence from a list is not a declared limitation. `docs/SANITIZE.md` makes the
same distinction in its own scope section and it is the reason that document is
trusted.

**Gates:** `gofmt`, `go vet`, `go build`, `go test ./... -count=1` against live
Postgres + Redis + MinIO, `shellcheck` on the new script if the repo uses it
elsewhere. Serially, never alongside a Kubernetes run.
