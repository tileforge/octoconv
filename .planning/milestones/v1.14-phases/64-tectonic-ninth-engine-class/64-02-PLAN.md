<objective>
Make `latex → pdf` actually happen, in a container that cannot reach the network
and cannot run a program the document names.

Purpose: after this plan a `.tex` file becomes a typeset PDF through the
registry, and the two security properties TEX-02 and TEX-04 assert are
properties of this build rather than of tectonic's documentation.
</objective>

## Task 1 — the argv builder, on its own

`internal/convert/tectonic.go`, a pure `tectonicArgs(inPath, outDir, bundlePath string) []string`:

```
-X compile <inPath> --untrusted -b <bundlePath> -o <outDir> -p
```

Its own function for the reason `ps2writeArgs` and `ocrPageCountArgs` are:
**the argument vector is the security-relevant part**, and a test can assert on
it directly instead of reaching into a running process.

Each flag gets a comment saying why it is there or why its absence is
deliberate:

- `--untrusted` — the whole of TEX-04. Not a default that a later flag can
  undo: it makes shell-escape un-enableable *regardless* of `-Z shell-escape` on
  the same command line.
- `-b <bundlePath>` — the baked-in `.ttb` from 64-01. This is what makes TEX-02
  true; without it tectonic reaches for `relay.fullyjustified.net`.
- `-p` — print engine chatter. **This is where 64-03's package-name extraction
  gets its input from**, so removing it silently breaks a later requirement.
- **no `-r/--reruns`** — tectonic reruns until convergence on its own. Pinning a
  count replaces "as many passes as this document needs" with a number, which is
  the exact thing 64-05's measurement exists to characterise.
- **no `-k/--keep-intermediates`** — nothing wants the `.aux`/`.bcf` litter.

**Verify:** a table test on the returned slice, asserting `--untrusted` is
present and that no `-Z` flag appears. Assert on the SLICE, not on a joined
string — a substring check would pass on `--untrusted-ish`.

## Task 2 — the converter

`TectonicConverter` implementing `Converter`, `Pairs()` returning
`{From: "latex", To: "pdf"}`, `Convert` running through `runCommand` (the
hardened `Setpgid` + process-group-kill runner — a typesetting engine that hangs
must not leave orphans).

Register in `converters.go`. **`Registry.Register` PANICS on a triple collision
since Phase 57 D-09** — confirm `(convert, latex, pdf)` is unclaimed before
registering. It is today (pandoc serves `latex → {html, docx, epub, md}`,
`pandoc.go:49`), but re-check rather than assume: a collision here is a startup
crash of every process that imports the package.

Output missing or zero-length is a failure, not a success with an empty result —
`sanitizePDF`'s own intermediate check exists because gs exits 0 on inputs it
declines to render, and the same trap applies to a TeX engine that "succeeds"
having typeset nothing.

**Verify:** a minimal `article` compiles to a PDF with `%PDF-` magic bytes and
non-trivial length. **This is also where 64-01 Task 1's floor gets determined** —
the first document that compiles tells you what the base format actually needed.

## Task 3 — the container

`Dockerfile.tectonic-worker`, cloning `Dockerfile.pandoc-worker` byte-for-byte in
shape:

- `ARG TECTONIC_VERSION=0.17.0`, per-arch `ARG TECTONIC_SHA256_AMD64/ARM64`,
  `ARG TARGETARCH` dispatch, `curl -fL --retry 5 --retry-delay 5`,
  `sha256sum -c`, extract the one binary.
- The same treatment for the bundle artifact from 64-01 Task 5: pinned URL,
  pinned SHA, verified before use.
- Runtime stage on `debian:bookworm-slim`, `USER nobody`, `ca-certificates` only.

**Both SHAs are computed locally**, never taken from a published checksum page —
`Dockerfile.pandoc-worker`'s comment states the rule and it applies to the
artifact we publish ourselves as much as to the one we do not.

**No `biber`, no `tectonic-biber`, and no Perl** (D-07). This is not an omission
to be tidied up later by someone adding "full biblatex support"; it is the
guarantee. Put that sentence in the Dockerfile, next to the absence, because an
absence cannot otherwise explain itself.

**Verify:** `docker build` succeeds for the host arch. Then, in the built image:
`command -v biber || command -v tectonic-biber` finds nothing, asserted by a
test rather than by eye.

## Task 4 — TEX-04, proven by running and by inversion

Commit `internal/convert/testdata/tectonic/hostile_shell_escape.tex` containing
BOTH vectors — `\write18{...}` and `\input{|"command"}` — each writing a
sentinel file to a temp path. `PROVENANCE.md` beside it records what each
construct is and what it would do if it worked.

The test compiles it **through `tectonicArgs`**, i.e. the production argv, not a
hand-written one. It asserts the sentinel files do not exist.

**Inversion, non-negotiable (D-06/D-03):** rebuild the argv with `--untrusted`
removed, run the same document, and assert the outcome CHANGES. Run it, record
the output under the phase's `evidence/`.

Without the inversion, this test proves only that the document failed to produce
a sentinel — which a typo in the fixture also achieves. Phase 60 rejected
`olevba` after the research recommended it unrun; the discipline is the same
one.

**A note on what this does NOT prove.** `--untrusted` gates shell-escape. It does
not obviously gate tectonic's external-tool pass (64-RESEARCH.md §2, recorded as
an UNVERIFIED reading). That path is closed here by Task 3's absence of a binary
to launch, not by this test — and the test comment must say so, or a later
reader will take this green test as covering more than it does.

## Task 5 — TEX-02, proven with the network actually cut

Run a conversion in the built container with networking disabled
(`docker run --network none`). It must succeed.

**Assert on the run, not on the Dockerfile.** "The bundle is baked in" is a claim
about the image; "it typesets with no network" is the property TEX-02 asks for,
and only one of the two can be checked by unplugging something.

Record the output under `evidence/`.

**Gates:** `gofmt`, `go vet`, `go build`, `go test ./... -count=1` against live
Postgres + Redis + MinIO, plus the two container runs above. Serially, never
alongside a Kubernetes run.
