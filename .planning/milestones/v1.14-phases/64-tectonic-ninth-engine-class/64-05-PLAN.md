## Task 1 — the corpus, committed, three classes

`internal/convert/testdata/tectonic/corpus/`, with a `PROVENANCE.md` recording
what each document is FOR:

1. **single-pass** — no references, no bibliography;
2. **cross-references** — converges in two passes (`\label`/`\ref`, a table of
   contents);
3. **bibliography** — `biblatex` with `backend=bibtex`, three or more passes.

Each in a few sizes, so per-pass cost can be separated from per-document
overhead. Every document uses only packages from the declared set (64-01) —
a corpus that needs a package the bundle lacks measures the gate, not the engine.

**Why committed rather than borrowed.** They are ours, so the measurement is
reproducible by anyone and re-runnable when the bundle changes. The operator
chose this over real consumer documents for v1; using real documents as a
later cross-check is an improvement, not a contradiction.

**Verify:** every corpus file converts successfully through the production path
before any timing is recorded. A corpus with a file that does not convert
measures nothing.

## Task 2 — the harness

`scripts/tectonic-timeout-measure.sh`, cloned from
`scripts/probe-timeout-measure.sh`, which is a known-good shape: it runs the full
pipeline, streams rows as they complete, bounds each file, **prints the
recommendation with its formula**, and fails the run if any file does not
convert.

It must additionally report **passes per document** — the whole point is per-pass
cost, and a wall-clock total cannot be divided by a number nobody recorded.
Tectonic reruns internally, so the pass count comes from parsing `-p` output.

**If the pass count cannot be recovered from the engine's output, say so** and
derive from a per-document cost with the pass classes as the ceiling axis
instead. That is a legitimate outcome; silently reporting a per-pass number that
was actually per-document is not.

**Verify:** the script runs against the corpus and prints a table plus a formula.

## Task 3 — the measurement, and the number

**Operator-run, in the measurement container at the same limits the worker gets**
(2 CPU / 1 GiB, per the chart), against the image built in 64-02 — not against
the host toolchain. Phase 60's own measurement recorded that the container
resolved gs 10.00.0 while the host had 10.07.1, and measuring the wrong binary is
measuring the wrong thing.

Derive as `ceil(per-pass cost x pass ceiling x margin)`, the shape OCR and probe
both use. State every term. State the margin and why it is that number.

**Never a p95.** `probe-timeout-measure.sh` reports one and `.env.example`
records, in as many words, why 600s was NOT derived from it: when cost is set by
a per-unit count and the corpus is chosen by hand, a wall-clock percentile
measures the choice of corpus. The same trap is here and it is worse, because
pass count varies more than page count does.

**Check the cap explicitly.** `RECONCILER_ACTIVE_STALE_AFTER` is 900s. State the
resulting margin as a percentage, as `.env.example` does for every other engine.
If the derived value does not clear it, the lever is a bound on the input (a
page or pass ceiling of this engine's own) — the Path-B move OCR already made
when its provisional 200-page ceiling breached the cap. **Do not shrink the
margin to fit.**

**Verify:** full output committed under the phase's `evidence/`, with the date,
the container limits, the tectonic version and the bundle SHA.

## Task 4 — the number, everywhere, with its derivation beside it

Set `TECTONIC_ENGINE_TIMEOUT` in `.env.example`, the chart ConfigMap, and **every**
`queue.NewClient()`-constructing service in `docker-compose.yml` (IN-02).
Re-derive `terminationGracePeriodSeconds` in `values.yaml` from it.

**The derivation travels with the number.** Every engine's block in
`.env.example` carries its own arithmetic, what was measured, what was reasoned,
and what the value does NOT cover. A measured number with no derivation beside it
is indistinguishable from a copied one, and PITFALLS.md Pitfall 7 records
copying as this project's named antipattern here.

If the measurement reveals that this engine needs an input bound of its own —
a maximum pass count, or a source-size ceiling — **that is a finding of this
phase**, recorded as a todo with its evidence, exactly as the probe page ceiling
was. It is not a premise to be invented now.

**Gates:** `gofmt`, `go vet`, `go build`, `go test ./... -count=1` against live
Postgres + Redis + MinIO, `scripts/ci-helm-checks.sh`, `yq` over
`docker-compose.yml`. Serially, never alongside a Kubernetes run.
