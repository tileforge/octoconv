## Decisions auto-resolved (user pre-delegated every choice to the recommended option)

**AR-1 — the stacking probe and the fallback when bytes do not bound render cost (research Open Question 1).**
Resolved as a `checkpoint:decision` with the recommended option, no stop:
- **Chosen:** a pre-registered probe (this plan) classifies each 3D format. A byte render ceiling (D-04 Path-B,
  operation-aware) is added only for a `byte_bound` format, where every probed stacking mechanism of that format stays
  within budget except copies whose break size is at or above the format's floor. For a `not_byte_bound` format the
  render stage deadline is the bound (74 R-01: a render timeout is terminal `cad_too_complex`, no retry). If any format
  is `not_byte_bound`, the global render deadline is the window remainder `R = 886 - guard - mesh - io`, computed in
  76-03 from measured guard, mesh and I/O. Every non-stacked ceiling cell must still fit `ceil(1.5 x W) <= R`, and
  stacked rows are classified margin, no_margin or refused against R. The limit is documented in docs/CAD.md Known
  limits (D-14, "any limit the measurement run adds"), and a live row in 76-08 proves the refusal ends terminal within
  the engine timeout.
- **Alternatives considered:**
  - (b) lower the byte ceiling anyway: it refuses legitimate files and still does not bound NAUO or cube stacks of a few KiB.
  - (c) a heuristic stacking guard: forbidden by D-04 and Deferred.
  - (d) raise the timeout, the 900 s window or the pod: forbidden by 74 R-01 and D-04.
- **Rating:** reversible for the probe itself. The one-way door (an operation-aware 413 ceiling) is entered only in
  76-05, and only for a `byte_bound` format. That door was decided by the user in D-04, so no extra checkpoint is
  inserted.
