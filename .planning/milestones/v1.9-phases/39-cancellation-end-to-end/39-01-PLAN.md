<objective>
Deliver the DB-authoritative cancel: `Repo.Cancel` (a thin wrapper on the existing
guarded `transition()` helper) plus the `POST /v1/jobs/{id}/cancel` handler and route.
This is the correctness layer (CNCL-01, CNCL-02) — after this plan a queued/active job
flips to `canceled` in Postgres and the API contract is complete. Killing the real
in-flight engine process (the speed layer) is Plans 02/03; the guarded-transition
allow-list is the sole correctness backstop and does not depend on the kill.

Purpose: Give clients an authoritative, idempotent, race-safe cancel endpoint.
Output: `Repo.Cancel`, `handleCancelJob`, the route, and full unit/integration tests.

Locked decisions honored: D-01 (reuse `transition()`, stamp `finished_at`), D-02
(404-not-403 ownership mirroring `handleGetJob`; idempotent 200 on terminal; 200 on
the terminal-race), D-09 (respond 200 not 202; kill is async/best-effort, never
blocked on in the request path). D-08: NO webhook is fired on cancel (deferred) — do
not add one. This plan wires a nil-safe `CancelPublisher` seam on `Server` so Plan 03
can inject the real pub/sub publisher without touching this handler again.
</objective>

| API → Postgres | The guarded transition is the single authority for the status change. |

|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | Information Disclosure | handleCancelJob ownership check | mitigate | 404-not-403 for cross-client/not-found (mirror handleGetJob) — cancel of another client's job is indistinguishable from not-found; verified by a cross-client 404 test. |
| T-39-02 | Tampering | Repo.Cancel terminal overwrite | mitigate | Idempotent 200 on already-terminal + guarded-transition allow-list ({queued,active}) reject any done/failed→canceled flip; a terminal-race re-reads and returns the real current status, never overwrites. |
| T-39-03 | Denial of Service | async kill (D-09) | accept | Handler returns 200 without blocking on process death; the best-effort publish cannot stall the request (error ignored). |
| T-39-SC | Tampering | dependencies | accept | Zero new Go dependencies introduced (stdlib + existing pgx/chi/uuid); no package-manager install, so no legitimacy gate applies. |
