Package convention (mirror internal/convert's Default singleton pattern):
  package cancel
  const Channel = "job:cancel"
  type Registry struct { mu sync.Mutex; m map[uuid.UUID]context.CancelFunc }
  func NewRegistry() *Registry
  var Default = NewRegistry()                         // process-wide singleton, like convert.Default
  func (r *Registry) Register(id uuid.UUID, cancel context.CancelFunc)
  func (r *Registry) Deregister(id uuid.UUID)
  func (r *Registry) Cancel(id uuid.UUID)             // lookup; call the CancelFunc if present; no-op otherwise

  type Publisher struct { rdb *redis.Client }
  func NewPublisher(rdb *redis.Client) *Publisher
  func (p *Publisher) Publish(ctx context.Context, id uuid.UUID) error   // rdb.Publish(ctx, Channel, id.String())

  type Subscriber struct { rdb *redis.Client; reg *Registry }
  func NewSubscriber(rdb *redis.Client, reg *Registry) *Subscriber
  func (s *Subscriber) Run(ctx context.Context)      // Subscribe(Channel); loop over the channel; parse uuid; reg.Cancel(id); return on ctx.Done() with pubsub.Close()

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → Redis (publish) → workers (subscribe) | Fire-and-forget fan-out; delivery is NOT guaranteed (a disconnected worker misses it). |
| Redis message → Registry.Cancel | An unparseable/spurious payload must never crash a worker. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-04 | Denial of Service | Subscriber.Run goroutine | mitigate | Run selects on ctx.Done() and Close()s the pubsub — no goroutine/connection leak across worker lifetime (verified in Plan 04's live proof; unit-tested for clean return here). |
| T-39-05 | Tampering | reg.Cancel on received payload | mitigate | uuid.Parse validates the payload; an unparseable message is skipped, and Cancel of an unknown/unregistered id is a no-op — a stray publish cannot cancel an unrelated job or crash the worker. |
| T-39-06 | Repudiation/Correctness | missed pub/sub signal | accept | D-05/D-12: pub/sub is a latency optimization only; a missed signal means the job runs to completion/timeout and its terminal Mark* is rejected by the allow-list (Plan 01/Plan 04) — wasted compute, never state corruption. No periodic DB re-poll (D-12). |
| T-39-SC | Tampering | dependencies | accept | Zero new Go dependencies — go-redis is already an asynq transitive dep in go.mod; no package-manager install, so no legitimacy gate applies. |
</threat_model>
