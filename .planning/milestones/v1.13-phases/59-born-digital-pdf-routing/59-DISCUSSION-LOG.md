## Детектор текстового слоя

### Как inspect отвечает на вопрос о текстовом слое без pdftotext в API-образе

| Option | Description | Selected |
|--------|-------------|----------|
| Инфлейт content streams | stdlib compress/zlib, поиск операторов Tj/TJ под бюджетом Tracker; не слепнет от /ObjStm | ✓ |
| Структурный прокси через /Font | Дешевле, без распаковки, но /Font — обычный словарь и может лежать внутри /ObjStm | |
| Всегда unknown в inspect | Решение оставить воркеру; BDPD-01 закрывается формально, клиент ответа не получает | |

**Notes:** решающим оказался факт из заголовка `internal/inspect/pdf.go:2-4` —
ISO 32000 §7.5.7 запрещает внутри `/ObjStm` только stream-объекты и словарь
шифрования, а текстовый слой живёт в content streams. Слепота, определившая всю
фазу 58, к этому чеку не применяется.

### Где в отчёте живёт вердикт

| Option | Description | Selected |
|--------|-------------|----------|
| Отдельное поле со своим статусом | text_layer в характеристиках, пара статус+причина | ✓ |
| Обычный Check в списке проверок | Даром получает механику честности, но ломает семантику Check | |
| Только внутри блока операций | Компактнее всего, но BDPD-01 требует наблюдаемого факта, а не следствия | |

### Чем ограничиваем decompression bomb

| Option | Description | Selected |
|--------|-------------|----------|
| Потолок на выход в тот же Tracker | Распакованные байты списываются в общий бюджет; исчерпание = work_ceiling_bytes | ✓ |
| Потолок плюс находка про ratio | То же плюс новый код находки — новая возможность за границами фазы | |
| Отдельный бюджет только на распаковку | Точнее по смыслу, но два счётчика = два места забыть списать | |

**Notes:** находка про ratio записана в deferred, не отвергнута по существу.

### Что делает текстовый слой пригодным

| Option | Description | Selected |
|--------|-------------|----------|
| Объём текста в единицах воркера | Непробельные байты строковых аргументов, тот же порог, что у гарда | ✓ |
| Любой текстовый оператор | Предсказуемо, но почти любой скан с колонтитулом получит present | |
| Объём плюс охват страниц | Ближе к «пригодный» и различает Mixed-PDF, но требует связывать потоки со страницами | |

**Notes:** третий вариант отвергнут ещё и потому, что ввёл бы половину
Opportunity 2, явно вынесенной из фазы scope fence'ом.

## Что считать маршрутом

### Что считаем маршрутом для born-digital PDF

| Option | Description | Selected |
|--------|-------------|----------|
| Извлекать вместо отказа на pdf→txt | Пара уже есть, pdftotext уже в образе, гард уже извлекает текст и выбрасывает его | ✓ |
| Отказ остаётся, но с указанием куда идти | Честнее сегодняшнего, но тупик остаётся тупиком | |
| Явный opt-in на принудительный OCR | Решает другую задачу и стоит против fail-closed линии | |

**Notes:** перед вопросом проверено по коду, что `ocrSourceFormats` × `ocrTargetFormats`
уже даёт пару `pdf→txt` (`ocr.go:34-35, 62-70`), и что `poppler-utils` уже стоит
в `Dockerfile.ocr-worker`. Это изменило постановку вопроса: маршрут не создаётся,
а разблокируется.

### Что делает born-digital PDF с таргетом hocr или alto

| Option | Description | Selected |
|--------|-------------|----------|
| Гонить OCR — гард таргет-зависимый | pdftotext боксов не даёт; OCR — единственный их источник | ✓ |
