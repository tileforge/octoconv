Содержание: суточный лимит считает in-flight (`queued`/`active`) джобы; из in-flight их выводит терминальный переход; застрявшая джоба остаётся in-flight без ограничения по времени и потому занимает бюджет клиента каждый следующий UTC-день; самолечение идёт через сweeper реконсилятора, который живёт в `cmd/webhook-worker` под advisory-lock — то есть при остановленном webhook-worker застрявшие джобы перестают рассасываться сами.

Написать это как эксплуатационный факт, а не как предупреждение о дефекте: поведение корректно и является ценой того, что суточный лимит вообще работает.

Здесь же — операторское средство из плана 61-01: `list-inflight` чтобы увидеть застрявшее с возрастом, `cancel-job -id <uuid>` чтобы снять. Явно сказать, что снимать надо этой командой, а не `UPDATE`, и почему: прямой апдейт не выполняет суточный роллап, поэтому чинит квоту и одновременно ломает её учёт.

Если в README есть раздел операторских команд — перечислить обе и там, чтобы оператор нашёл их по месту, а не только по контексту квот.
