Собрать НОВЫЙ zip, а не править существующий. SANI-04 требует физического отсутствия удалённого; редактирование на месте оставляет запись в центральном каталоге или дыру, которую можно прочитать.

Что не переносится в новый архив:
  - `word/vbaProject.bin` (и его аналоги для xl/ и ppt/);
  - части, опознанные как встроенные OLE-объекты (`IsOLECFB` по содержимому части, а не по имени: имя переносимо, сигнатура нет);
  - `docProps/*` с метаданными документа — по SANI-03.

Что правится при переносе:
  - `[Content_Types].xml` — снять `<Override>` удалённых частей и `<Default Extension="bin">`, если после удаления `.bin`-частей не осталось;
  - `*/_rels/*.rels` — снять `<Relationship>` на удалённые цели; ОСИРОТЕВШАЯ ссылка ломает открытие так же надёжно, как отсутствующий тип;
  - `<Override PartName="/word/document.xml">` — тип из macroEnabled в обычный (D-06).

**Закрытый словарь соответствия типов.** Пары macro-enabled → обычный (docm/dotm, xlsm/xltm, pptm/potm/ppsm и их типы содержимого) объявить одной таблицей, а не условиями по коду. Это ровно та форма, которую проект уже держит под doc-sync тестами, и она же даёт следующему формату одну строку вместо новой ветки.

Расширение выхода следует за типом: `.docm` → `.docx`. Записать в доккоммент, что имя выхода намеренно расходится со входом, и почему (D-06: тип, обещающий макросы, которых нет, — это ложь того же рода, которую фаза 59 вычищала из комментариев).

Уважать существующий структурный потолок на zip. Не заводить второй: два потолка — два места забыть, и это уже названный в проекте класс дефекта.

Три группы.

**Удаление.** В выходных БАЙТАХ нет сигнатуры OLE-CFB, нет имени `vbaProject`, нет маркера p-кода из фикстуры. Проверять байты: SANI-04 говорит «физически отсутствует».

**Согласованность — то, ради чего план написан.** После санитации:
  - каждый `<Override PartName>` в `[Content_Types].xml` указывает на СУЩЕСТВУЮЩУЮ часть;
  - каждый `<Relationship Target>` во всех `.rels` указывает на существующую часть;
  - `<Override>` для `/word/document.xml` несёт НЕ-macroEnabled тип;
  - архив открывается `zip.NewReader` без ошибки.

Эти четыре утверждения и есть «файл откроется». Тест обязан проверять их ОБЩИМ обходом, а не перечислением известных имён: правило «ни одна ссылка не висит» переживёт добавление формата, а список имён — нет.

**Инверсии, по одной на каждую из трёх правок.** Временно вернуть `<Override>` удалённой части — обязан покраснеть тест согласованности. Временно вернуть `<Relationship>` — тот же. Временно оставить macroEnabled тип — обязан покраснеть третий. Три отдельных отката, потому что план вводит три отдельных свойства, и один откат доказал бы одну треть.

Результаты с именами покрасневших тестов — в SUMMARY.
