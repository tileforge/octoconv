4. `FairnessGuaranteeIsPerClientNotGlobal` — a SECOND client, also capped at `max_concurrent = 1`, creates a job successfully while the first client sits at its cap. This makes FAIR-01 falsifiable: the cap bounds one client's occupancy and is not a global throttle, so at cap K and maxReplicaCount M one client holds at most K of M slots and the remaining M minus K stay reachable by others. 5. `ConcurrentBurstBoundedUploadWaste` — a fresh client in `enforce` mode with `max_concurrent = 1` (K = 1) and no in-flight job. Fire N = 8 identical multipart POSTs simultaneously from 8 goroutines released by one closed start-barrier channel, collect each response over a buffered channel, and record the stub storage's upload counter immediately before and after the burst. Assert, in this order:
   - the authoritative guarantee, which is the load-bearing FAIR-01/QUOT-02 property and must fail loudly if it ever regresses: exactly 1 response is 202, exactly 7 are 429, every one of those 7 decodes to `code == "quota_exceeded"` and carries a parseable `Retry-After`, and `SELECT count(*) FROM jobs WHERE client_id = $1 AND engine = 'image' AND status IN ('queued','active')` is exactly 1. No response may be any other status — the rate limiter is configured at 10000 RPM precisely so a competing 429 is impossible;
   - the residual, measured rather than assumed: let `wasted := uploadsAfter - uploadsBefore - 1` (the admitted job's own upload is not waste). Assert `wasted >= 0` and `wasted <= N - K`, i.e. at most 7, and `t.Logf` the observed value so each run records the real number. Put the derivation in a comment: `PreAdmit` is unlocked by design (D-07/D-15), so every request that reads a below-cap count before any sibling commits its insert will upload and only then be rejected at `admitLocked`; the waste per burst is therefore at most N minus K uploads, `(N - K) x MAX_INPUT_BYTES` bytes, with N bounded by the upstream per-client rate limiter. State in the same comment that this bound is looser than D-15's: D-15's `K` is a small, phase-owned value this very admission mechanism enforces structurally, whereas `N`'s ceiling is `internal/ratelimit`'s operator-configured fixed-window RPM counter — a different package's independently-tuned knob that is not a burst or concurrency control, so `N` can exceed `K` by orders of magnitude. The framing is D-15's (disclose, bound, measure); the tightness is not;
   - the steady state, which is the property ROADMAP SC2b actually names: with the client now at its cap, send ONE further sequential POST, assert it is 429 with `code == "quota_exceeded"`, and assert the storage upload counter did not move at all across it. This is what makes "an over-quota client repeatedly burns S3" false: the burst waste is a one-time transient at the cap boundary, and every retry afterwards costs zero bytes.
   Run this subtest as part of the suite's `-race` invocation; the goroutines share only the `*http.Client`, the response channel and the counters, all of which must be race-clean.

Use a fresh client id per subtest so repeated `-count=1` runs are deterministic. Never assert on REST error text — decode the JSON body. On the MCP leg assert with `strings.Contains` over `resultText`, which is that layer's only observable.

|----------|-------------|
| test harness → real Postgres | The integration test writes real rows to the same schema production uses; a leaked fixture could pollute an operator's database if pointed at one. |
| documented error contract → every API consumer | Publishing a code taxonomy commits the service to it; a wrong or over-broad document invites clients to branch on fields that do not exist. |
| KEDA → octoconv_queue_depth | The autoscaling contract: any change to that metric's semantics silently breaks scale-from-zero for all seven engine classes. |
