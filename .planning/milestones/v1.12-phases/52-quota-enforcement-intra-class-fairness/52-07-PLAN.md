<objective>
Close the operator-side silent-failure mode: `manage-clients set-limit <id>
images 5 - -` (note the typo) succeeds today, prints a success line, and
`show-limits` echoes it back — while `loadQuotaState`'s `LEFT JOIN ... ON
l.engine = $2` never matches `image`, so the client stays unlimited and the
operator believes a cap is in force.

Purpose: QUOT-01 is already SATISFIED — this plan does not re-claim it. It
hardens the operator surface that expresses QUOT-01's limits, without touching
the storage contract, the schema, or the read path. The migration deliberately
refuses a DB-level engine allow-list (a stale CHECK there would abort `INSERT
INTO jobs` for a new engine class, breaking conversion rather than merely
failing to enforce a limit); the CLI is the correct place to catch a typo,
because a mistake there costs nothing but an error message.

Output: a single compile-time source of truth for the engine-class list with a
completeness guard, and a fail-closed check on the one subcommand that can
create the bad state.
</objective>

`AllEngines() []string` returns the seven engine classes in a fixed, documented order — `EngineImage`, `EngineDocument`, `EngineHTML`, `EngineAudio`, `EngineAV`, `EngineOCR`, `EnginePandoc` — constructed fresh on every call so a caller cannot mutate the source of truth through the returned slice. Exact, case-sensitive comparison with no trimming and no normalization: engine-class strings are stored verbatim in `jobs.engine` and `client_limits.engine`, and `NormalizeFormat` is for file formats, not engine classes — applying it here would silently accept `Image` and write a row that `loadQuotaState`'s equality join can never match, which is the exact defect this plan closes. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell -> client_limits row | The CLI is the only writer of quota configuration; an unvalidated string here becomes a permanently inert row that reads as an enforced limit. |
| client_limits.engine -> admission LEFT JOIN | The join is exact equality; any mismatch degrades silently to "unlimited" rather than failing loudly. |
| engine-class constant block -> every consumer | Adding an eighth engine class without updating the list would make the CLI reject a legitimate engine — a self-inflicted outage of the operator surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-39 | Spoofing | an operator-believed limit that is never matched (`set-limit ... images ...`) | mitigate | `validateEngine` rejects any token outside `convert.AllEngines()` before `repo.SetLimit` runs, so the inert row cannot be created; pinned by `TestValidateEngine` and by a recorded live run asserting zero rows with `engine = 'images'`. |
| T-52-40 | Denial of Service | a stale allow-list rejecting a newly added, legitimate engine class | mitigate | The list is derived from the same const block every converter already uses, and `TestAllEnginesCoversEveryEngineClass` cross-checks it against `Default.Classes()`, so adding an engine without updating the list fails a test rather than surfacing as a CLI outage. The check lives only in the CLI — never as a DB CHECK — so it can never abort `INSERT INTO jobs` (0013's stated reason). |
| T-52-41 | Tampering | an existing typo'd row becoming unremovable | mitigate | `clear-limit` and `show-limits` deliberately skip validation, so any row written before this change can still be listed and deleted through the CLI; the reasoning is recorded at the call site so it is not "fixed" later. |
| T-52-42 | Elevation of Privilege | case-folding or trimming the engine argument into a match | mitigate | `IsKnownEngine` is documented as exact and case-sensitive with no `NormalizeFormat` call, and the CLI test asserts `"Image"`, `"IMAGE"`, `" image"` and `"image "` are all rejected. |
| T-52-SC | Tampering | npm/pip/cargo installs | mitigate | No package is installed; `go.mod`/`go.sum` are unchanged. This plan adds two functions and one test file. |
</threat_model>
