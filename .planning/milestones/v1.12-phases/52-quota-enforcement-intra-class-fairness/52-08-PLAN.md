<objective>
Complete the daily ledger and pin the isolation assumption the whole admission
mechanism silently rests on.

Purpose: two defects share one root cause with the gap plan 52-06 closes — the
daily rollup is an incomplete ledger, and its correctness depends on unstated
invariants. `Cancel` never calls `recordUsage`, so `create -> cancel -> create
...` consumes uploads, storage and (if a worker picked the job up) real engine
CPU against a daily cap that never advances. That was defensible in Phase 51,
when the rollup was reporting-only; Phase 52 made the same rollup the
enforcement input, which turns it into a quota-evasion path. Separately,
`admitLocked`'s post-lock re-check only observes commits made while it waited on
the advisory lock because the transaction is READ COMMITTED and takes a fresh
snapshot per statement — an invariant nothing in this repository states or
enforces, so a one-line DSN change would silently over-admit with no error and
no serialization failure.

Output: a canceled job that costs what it consumed, an isolation level that is
declared rather than inherited, and tests that fail if either regresses.
</objective>

| admission transaction -> Postgres snapshot semantics | The post-lock re-check's correctness is a property of the isolation level, not of the code, and the isolation level is deployment configuration. |
| operator/DSN configuration -> enforcement correctness | A connection-string edit made by someone who never reads `internal/jobs` can silently disable the cap. |
