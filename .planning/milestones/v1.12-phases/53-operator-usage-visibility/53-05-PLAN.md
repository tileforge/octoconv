<objective>
Close the single verification gap (53-VERIFICATION.md Gap #1 / 53-REVIEW.md CR-01 / ROADMAP SC2 / OPSV-02): `handleSystemUsage`'s merge builds its emitted key set as `usageByKey ∪ limitsByKey`, and `limitsByKey` is populated only from `clients.LimitWithMeta` rows whose `Engine` is non-nil. A nil-`Engine` row — the documented, load-bearing signal for "this client has no `client_limits` row at all", and per ROADMAP SC1 the default state of every freshly-provisioned client — feeds only the `meta` map and never enters the key set. A client with no limits row, no usage in the window and no in-flight jobs therefore emits ZERO rows, and `?client_id=<a real idle unlimited client>` returns `{"usage":[]}`, byte-identical to a `client_id` matching no client at all.

`internal/clients/limits.go:116-119` states in capitals that these rows "MUST NOT be discarded by the caller". This plan stops discarding them.

Purpose: make OPSV-02 answerable for the fleet's default state — an operator must be able to see "this client exists, has enforcement_mode X, and is unlimited" — WITHOUT weakening ROADMAP SC3's no-leak contract.
Output: a merge that seeds its key set from every client in `meta`, five new tests including the previously-untested "zero usage AND zero limits" cell, and an OpenAPI contract that documents the synthetic row.
</objective>

<design_resolution>
## The SC2 × SC3 tension, resolved explicitly

The fix makes a real idle client distinguishable from a nonexistent one. That is, mechanically, an existence oracle for arbitrary UUIDs — but only for callers who already passed `requireOperator`. It does NOT weaken SC3, for three independent reasons, and the plan encodes all three as tests rather than assertions:

1. **Non-operators never reach the merge.** `requireOperator` is mounted on the `/system/usage` chi sub-router (`routes.go:77-80`) and returns the `noSuchPreset` 404 before routing, with zero repo calls. Nothing in this plan touches that gate, and Task 2 adds a regression test that proves it holds with a POPULATED limits fake (the fix's new data path) — the previous SC3 tests only exercised empty fakes.
2. **Narrowing reveals nothing the un-narrowed shape does not.** After this fix, `GET /v1/system/usage` with no `?client_id` enumerates every client (id, name, enforcement_mode) to the same operator caller. `?client_id=X` therefore adds no information an operator cannot already obtain in one request.
3. **The nonexistent-UUID response is unchanged.** `ListAllLimits` returns zero rows for a UUID matching no client, so `meta` is empty, so no synthetic row is seeded, so the body stays `{"usage":[]}` — byte-for-byte what it is today. Task 2 asserts this directly.

**Locked row shape for the synthetic row:** `engine: ""` (a new named constant `usageEngineNone`), real `client_name` and `enforcement_mode` from `meta`, all `used_terminal`/`used_in_flight` counters zero, all `limits` and all `remaining` fields `null`. Engine stays a plain `string` in JSON — do NOT change it to a nullable type, because `docs/openapi.yaml:1057` lists `engine` in `required` and existing consumers/tests decode it as a string.
</design_resolution>
