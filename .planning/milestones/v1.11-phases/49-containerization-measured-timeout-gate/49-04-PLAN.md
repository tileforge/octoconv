## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> pandoc-worker (live) | untrusted markdown crosses into pandoc (`--sandbox`) in the container |
| pandoc-worker -> webhook receiver | signed terminal webhook delivery over the e2e-relaxed SSRF path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-10 | Spoofing | webhook payload authenticity | mitigate | the E2E HMAC-verifies the signed webhook against WEBHOOK_SIGNING_SECRET (assertSignedWebhook) — proving signature parity between pandoc-worker and the webhook-workers. |
| T-49-11 | Information Disclosure | presigned download exposure | accept | e2e-only: presigned URLs are short-TTL and the SSRF relax is confined to docker-compose.e2e.yml (existing CI posture). |
| T-49-12 | Tampering | raw HTML/TeX passthrough in md input | mitigate | pandoc runs `--sandbox` with per-source raw_html/raw_tex extensions disabled (pandoc.go, unchanged) — the live E2E exercises the real hardened argv path in the container. |
