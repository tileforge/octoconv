<!-- The measurement invokes the SAME production argv the converter uses. -->

From internal/convert/pandoc.go (pandocConvertArgs / pandocReaderSpec):
  Production argv: `pandoc -f <readerSpec> -t <pandocFmt> --sandbox
  [--standalone when target is structural] <in> -o <out>`.
  readerSpec: md/html/epub -> "<fmt>-raw_html-raw_tex"; latex -> "latex-raw_tex";
  rst/org/docx -> bare fmt. pandocFormatName: "md" -> "markdown" (pandoc has no
  literal "md"). --standalone is added for structural targets html/latex/docx/epub.
  The valid (from,to) pairs are the CLOSED pandocPairTable — the corpus must
  only exercise pairs IN that table (e.g. md->{html,docx,epub}, latex->{html,docx,epub},
  html->{docx,epub}, docx->{html,epub}); NEVER an unlisted pair (it fast-rejects).

From internal/convert/markupsniff.go:
  PANDOC_MAX_INPUT_BYTES is the input-size cap (enforcePandocInputSize) and is
  this phase's Path-B lever (analog of OCR_MAX_PAGES). cmd/pandoc-worker default 50<<20.

From internal/queue/client.go:
  NewClient() reads PANDOC_MAX_RETRY (default 2) + PANDOC_ENGINE_TIMEOUT (default 90s)
  -> PandocUniqueTTL. These TWO are the IN-02 parity vars (mirror OCR_MAX_RETRY +
  OCR_ENGINE_TIMEOUT, already present on all 9 existing services in docker-compose.yml).

Reconciler CAP: RECONCILER_ACTIVE_STALE_AFTER = 15m = 900s (webhook-worker-1/-2).
Derivation (documented in the script, NOT computed to a committed value here):
  PANDOC_ENGINE_TIMEOUT = ceil(worst-cell p95_sec x 2.0), MUST be < 900s.
  Pandoc cost is per-conversion (input SIZE x (from,to) pair), NOT per-page —
  so there is NO OCR_MAX_PAGES-style multiplier; the p95 IS the per-conversion cost.
IN-02 nuance (mirror ocr): PANDOC_MAX_INPUT_BYTES + PANDOC_WORKER_CONCURRENCY are
  pandoc-worker-ONLY (analogs of OCR_MAX_PAGES + OCR_WORKER_CONCURRENCY, NOT read by NewClient).
