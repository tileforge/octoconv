<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| KEDA PromQL scaler -> api /metrics | scaler decisions depend on an external metric that can be absent (api unreachable/unscrapeable) |
| KEDA/HPA downscale -> in-flight OCR job | a genuine N->N-1 downscale can SIGTERM a pod mid-conversion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-01 | Denial of Service | scaledobject-ocr PromQL scaler | mitigate | WR-01 triad VERBATIM (D-03): `ignoreNullValues: "false"` makes a sustained absent PromQL read as scaler ERROR, and `fallback {failureThreshold:3, replicas:1}` holds one OCR replica instead of falsely scaling to zero behind an api outage with a live backlog |
| T-46-02 | Denial of Service | scaleDown stabilization vs 744s worst-case job | mitigate | `scaleDownStabilizationSeconds: 900` (> 744s, under the 900s/15m reconciler cap, D-01) — a genuine downscale never races a live OCR job |
| T-46-03 | Tampering (data loss) | ocr-worker pod termination vs in-flight job | mitigate | `terminationGracePeriodSeconds: 774` (>= OCR_ENGINE_TIMEOUT 744) + cmd/ocr-worker graceful shutdown — a SIGTERM'd pod finishes the in-flight OCR before SIGKILL; live-proven in Plan 03 (SC4) |
| T-46-04 | Information Disclosure | secret.yaml literals | accept | committed template carries no literal secret; WEBHOOK_SIGNING_SECRET/DB creds resolve from values-local.yaml (.Values.secrets.*) — existing T-24-03 control, unchanged this plan |
| T-46-SC | Tampering | package / dependency installs | accept | zero new Go deps, zero package-manager installs this phase (pure Helm YAML + env); no [ASSUMED]/[SUS] packages to gate |

No high-severity unmitigated threat -> no blocking checkpoint required in this plan.
</threat_model>
