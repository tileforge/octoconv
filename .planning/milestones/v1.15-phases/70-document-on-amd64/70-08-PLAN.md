<objective>
Act on WR-02 per user decision 3: narrow veraPDF's `ro:/proc` by measurement so a confined JVM
cannot open /proc/<ppid>/environ or /proc/1/environ, keeping the JVM's container view (V0) equal.
The measurement decides; the fallback -- keep /proc, record the residual precisely, correct the
comment, add a todo -- is acceptable when a narrower grant is impossible or breaks the JVM.

Planner findings built into this plan:
- Landlock resolves each granted path in the helper process at Apply time. A `/proc/self` entry
  therefore names the HELPER's PID, and covers the JVM only if the launcher (a dash script) execs
  the JVM in place. V0 runs java directly and cannot see a fork, so V0L runs the JVM the way
  production does, through /opt/verapdf's launcher. The image class already relies on the same
  resolution (libvips grants /proc/self/auxv and /proc/self/status).
- The review's claim that a confined JVM reads other processes' environ was reasoned, not measured.
  N3's baseline on today's grant measures it; the comment fix states what was measured.
- tectonic grants no /proc at all (tectonic.go tectonicSystemReadOnly), so part of the review's
  "same exposure in html and tectonic" does not hold; html's grant does include /proc.

Purpose: close the path the environment scrub was believed to close, or record exactly what is left.
Output: two driver checks, the measurement, a narrowed (or justified) veraPDF set, honest comments, the record, one todo.
</objective>
