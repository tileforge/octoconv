<objective>
Confine the `av` class: every ffprobe and ffmpeg the AV converter runs on a job's path goes
through the job's engineExec (plan 01) under the set plan 02 re-measured — including the
streaming transcode, whose progress FIFO moves inside the job directory and whose
`-progress` option must be added to the engine's argv before wrapping (added after, it
would sit in front of `__sandbox-exec` and the worker binary would start as a second
worker instead of exec'ing ffmpeg). The worker refuses to start without confinement, and
a preflight proves the streaming re-encode and a denial by content before the first job.

The guard/probe shape the orchestrator asked about (decision 1) was checked for AV: all
three ffprobe probes run inside AVConverter (avPrepareConversion → avProbeSource), not in
the worker. Two exported functions nevertheless let any caller run ffprobe unconfined —
ProbeDuration and EnforceMaxResolution (the latter has no production caller); both become
unexported and take the engineExec. EnforceMaxDuration (audio's guard) keeps its
signature here; plan 05 threads the audio helper into it.

Output: confined AV converter and streaming runner, preflight, worker wiring, chart extraEnv, live gate.
</objective>
