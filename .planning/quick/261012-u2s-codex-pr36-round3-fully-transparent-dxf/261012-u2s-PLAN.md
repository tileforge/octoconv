# Quick 261012-u2s: codex PR #36 round 3 (a fully transparent DXF converts to nothing)

## Objective

Codex P2 at bae815e, `cad-dxf:311`: a DXF whose geometry is all fully transparent passes the helper's
`nothing_drawable` gate (the frame counts every record at any opacity), the SVG carries only alpha-0
paths and converts, and the Go PDF judge counts paint operators without the graphics-state alpha. Both
SVG and PDF are said to return a visually empty artifact as success.

Fix the class: **a result with nothing visible is `cad_empty_result` on every route (svg, pdf, render
png)**, decided in the helper and enforced again by Go, which does not trust the helper.

Second item (verifier note): a font with only OS/2 `fsSelection` bit 9 (OBLIQUE) set, and not bit 0,
is emitted upright. It must be emitted `oblique`.

## Premise check (done before planning)

Ad hoc DXFs drawn by the shipped image (`octoconv-cad-worker:latest`, the ebd2e53 build):

| DXF | helper | SVG | rsvg PDF content | Go PDF judge |
|---|---|---|---|---|
| LINE, CIRCLE, solid HATCH, all transparency 1.0 | `ok` | 3 paths at `stroke-opacity`/`fill-opacity` `0.000` | background `re f` only (cairo 1.16 drops alpha-0 paint) | `empty page: 1 paint operations` |
| LINE + TEXT, both 1.0 | `ok`, texts=1 | 1 path, 1 text at `0.000` | background only | `empty page` |
| LINE 1.0 + LINE 0.5 | `ok` | 2 paths | background + `/a1 gs` (`/CA 0.498 /ca 0.498`) + `S` | ok, paint_ops=2 |

So, for the shipped engine:

- SVG route: the codex finding holds. An all-transparent drawing converts to an SVG with nothing visible,
  which 261012-o2d documented as intended. That decision is reversed here.
- PDF route: the codex finding does not hold *today*. Cairo 1.16 omits paint whose alpha is 0, so the
  judge sees only the background and refuses. But the judge is blind to `/CA`, `/ca`, `/SMask` and the
  text rendering mode. A renderer that emits `/a1 gs` with `/CA 0` before `S` (or `3 Tr` before `Tj`)
  would pass. The judge has to read the graphics state rather than rely on cairo's habit.
- PNG route: J1 already refuses an inkless frame (it reads pixels, so alpha is already in).

## Decisions fixed before any code

1. **The frame stays paint-agnostic.** The bbox and frame keep counting every primitive at any opacity.
   A partly transparent drawing keeps its frame, and the measurements do not change for any drawing that
   still converts. Making the frame skip transparent records would move the frame of every drawing with
   a transparent element (text_alpha, text_alpha_faint) and the bbox in the measurements sidecar.
2. **Visible element** (helper and Go use the same definition):
   - a shape (path, polyline, polygon, line, circle, ellipse, rect) outside `defs`/`clipPath` whose
     effective fill is not `none` with effective `fill-opacity` > 0, or whose effective stroke is a colour
     with effective `stroke-opacity` > 0 and effective `stroke-width` > 0; a `line` has no fill; a rect,
     circle or ellipse with a zero dimension, a path with no drawing command, and a polyline or polygon
     with a single point draw nothing;
   - a text with at least one non-space character whose effective fill (text or any tspan) is not
     `none` with opacity > 0, or that inherits a visible stroke;
   - "effective" means the element's own attribute, else the nearest ancestor `g`'s, else the SVG
     default (fill black, fill-opacity 1, stroke none, stroke-opacity 1, stroke-width 1). The allowlist
     admits no `opacity`, `style` or `class`, so there is nothing to multiply.
3. **Helper:** count visible elements as they are emitted (stroke with opacity > 0 and width > 0, fill
   with opacity > 0, text with opacity > 0), for both render backends (the CSS-class one used by
   `TEXT_AS_OUTLINE` included). No visible element: verdict `empty`, reason `nothing_visible`, exit 3, no
   outputs. Exit 3 already maps to `ErrCADNothingDrawable` + `ErrCADEmptyResult` = `cad_empty_result`.
4. **Go SVG validator:** `CADSVGFacts.Visible` counts visible elements by rule 2. `dxfDrawing` requires
   the client and render-only SVG to agree on it (else `ErrCADSVGRejected`, the outputs disagree), and
   refuses 0 with `ErrCADNothingDrawable` + `ErrCADEmptyResult`, before any rsvg run, on all three routes.
5. **Go PDF judge:** a paint operator is ink only if the graphics state lets it show. The state tracks
   `/CA` (stroke alpha), `/ca` (fill alpha) and `/SMask` from the named ExtGState and the text rendering
   mode `Tr`, and `q`/`Q` save and restore them. `S`/`s` need `CA` > 0; `f`/`F`/`f*` need `ca` > 0;
   `B`/`B*`/`b`/`b*` need either; a text show needs a fill mode (0, 2, 4, 6) with `ca` > 0 or a stroke
   mode (1, 2, 5, 6) with `CA` > 0 and at least one glyph code; any soft mask other than `/None` makes
   the operator unprovable, so it is not ink. A `gs` naming an ExtGState that the page resources do not
   hold, or an alpha that is not a number in [0, 1], is a rejection. `InkOps` joins the facts; the
   "empty page" rule becomes `InkOps - 1 < 1` (the first ink is the `-b white` background).
6. **Error message** for `ErrCADNothingDrawable` names fully transparent drawings.
7. **Font slant:** a face is slanted when `fsSelection` bit 0 or bit 9, or `head.macStyle` bit 1 is set,
   or its subfamily name says Oblique or Italic; it is `oblique` when bit 9 is set or the subfamily says
   Oblique, `italic` otherwise. The old code only reached the oblique test through the italic bits.
