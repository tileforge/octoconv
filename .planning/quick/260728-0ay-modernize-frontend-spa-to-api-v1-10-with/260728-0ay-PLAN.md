GET /v1/formats  (internal/api/formats_handlers.go) — auth required (401 without key):
  { "engines": { "<class>": { "pairs": [ ["png","webp"], ["jpg","png"], ... ] }, ... } }
  - Keys of `engines` are engine-class names (image, document, html, audio, video/av, ocr — whatever the registry reports; DO NOT hardcode the class list, iterate the map).
  - Each pair is a 2-element array [from, to]. The set of selectable TARGET formats = the deduped union of pair[1] across ALL engines.

POST /v1/jobs  (multipart) -> 202 (internal/api/handlers.go handleCreateJob):
  form fields (confirmed constants, handlers.go:25-30):
    file             = the File (required)
    target           = target format string (required)  [already correct in current api.ts]
    opts             = OPTIONAL JSON STRING, e.g. {"language":"eng"} for OCR (compared to "{}" server-side, so send raw JSON text; omit the field entirely when empty)
    (callback_url, progress_webhook, preset exist server-side but are OUT OF SCOPE here)
  response body: { "job_id": "<uuid>", "status": "queued", "opts": {...}?  }

GET /v1/jobs/{id}  -> 200 (internal/api/handlers.go handleGetJob):
  { "job_id": string,
    "status": "queued"|"active"|"done"|"failed"|"canceled",
    "opts": {...}?,                         // present only when non-empty
    "progress_pct": number | null,          // ALWAYS present; null for non-av engines / pre-first-tick
    "eta_seconds": number | null,           // ALWAYS present; null when unknown
    "download_url": string?,                // present only when status==done and an output exists
    "error_code": string?,                  // present only when status==failed
    "error_message": string? }              // present only when status==failed

GET /v1/jobs/{id}/events  (SSE)  (internal/api/sse.go):
  - Content-Type: text/event-stream. Named events framed as:
        event: progress\n
        data: {json}\n
        \n
  - progress data payload (non-terminal): { "status": string, "progress_pct": number|null, "eta_seconds": number|null }
  - terminal event: also `event: progress` with data { "status": "done"|"failed"|"canceled" } (NO progress_pct/eta, NO download_url — client does a normal GET /v1/jobs/{id} for the result).
  - heartbeat: a comment line `: keepalive\n\n` (starts with ':') — IGNORE these.
  - Server closes the stream after the terminal event.
  - CRITICAL: browser EventSource CANNOT set the Authorization header. MUST use fetch() + response.body.getReader() (ReadableStream) with header `Authorization: ApiKey <key>` and parse the stream manually.

POST /v1/jobs/{id}/cancel  -> 200 (internal/api/handlers.go handleCancelJob):
  { "job_id": string, "status": "canceled" }  (idempotent; already-terminal returns current status)

Error envelope (all endpoints): { "error": "<message>" } — current parseResponse already reads `error`. Keep it.

Terminal statuses (isTerminalStatus, handlers.go:780): done, failed, canceled.
