<objective>
Третий круг ревью нашёл тот же класс на слой глубже: второй круг научил сканеры честно сообщать «я упёрся», но часть вызывающих этот сигнал роняет. Пока исчерпание — обычное возвращаемое значение, которое можно молча не использовать, четвёртый круг найдёт следующее уроненное.

Сделать так, чтобы ронять было нечего.

Purpose: три круга ревью нашли один класс тремя разными слоями. Причина не в невнимательности исполнителей, а в форме сигнала.
Output: приёмник неполноты, из которого отчёт читает полноту напрямую; сканеры на него отмечают; флаги исчерпания как возвращаемые значения исчезают.
</objective>

<design>
Сегодня: сканер возвращает `ceilingHit bool` рядом с результатом, вызывающий обязан протянуть его дальше, а `buildCoverage` собирает полноту из того, что до неё дошло. Каждый круг ревью находит очередное место, где не дошло.

Целевая форма: у операции есть один приёмник неполноты, доступный каждому сканеру. Сканер, прекративший работу из-за СОБСТВЕННОГО потолка сервиса, отмечает это на приёмнике. `BuildReport` читает полноту оттуда. Вызывающему нечего протягивать, а значит нечего забыть.

Опорные точки, которые уже есть:
- `Tracker` (`budget.go`) уже существует как объект на операцию и уже доходит до `BuildReport` (`report.go:65`). Он — естественный носитель либо естественный владелец приёмника.
- Анализаторы сегодня Tracker НЕ получают: им передаётся только `maxBytes int64` (`AnalyzePDF`, `AnalyzeImage`, `AnalyzeMedia`, `AnalyzeContainer`/`AnalyzeContainerWith`). Значит сигнатуры меняются — это ожидаемая часть работы, а не отклонение.

Три свойства, которые обязаны сохраниться:
1. **Структурная слепота НЕ делает отчёт выборочным**, исчерпание собственного потолка — делает. Приёмник обязан нести это различие. Схлопывание в «что-то пошло не так» уничтожит то, ради чего фаза существует.
2. **Причина остаётся у конкретной проверки.** Приёмник отвечает за полноту ОТЧЁТА; статус отдельной проверки (`unknown` + причина) остаётся там, где он сейчас.
3. Уже доказанные свойства не ослабляются.
</design>

Ввести приёмник неполноты, доступный каждому сканеру на время одной операции, и перевести на него ВСЕ места, которые сегодня сообщают об исчерпании возвращаемым значением.

Конкретная форма — на усмотрение исполнителя, но она обязана удовлетворять проверяемому свойству: **вызывающий не может получить полный отчёт, если какой-либо сканер отметил исчерпание.** Не «не должен», а не может — потому что полнота больше не собирается из того, что ему передали.

Естественный кандидат — расширить `Tracker` (он уже на операцию и уже доходит до `BuildReport`) либо завести отдельный тип, которым `Tracker` владеет. Анализаторы начинают принимать его вместо голого `maxBytes` (или вместе с ним, если бюджет и приёмник разумнее держать раздельно).

Сохранить различие двух видов неполноты. Структурная слепота (`/ObjStm`, hex-эскейп, токен в теле потока, нераспознанный формат) отмечается на проверке и НЕ трогает полноту отчёта. Исчерпание собственного потолка (байты, время, счётчики итераций, лимит вхождений, лимит частей) отмечается на приёмнике И делает отчёт выборочным.

Убрать возможность обойти приёмник: после перевода ни один анализатор не должен возвращать признак исчерпания наружу как часть своего результата. Если где-то он остаётся нужен внутри функции — это локальная переменная, а не элемент контракта.

Три из четырёх замечаний закрываются Task 1 как следствие — но обязаны быть проверены отдельными тестами, иначе «закрыто следствием» остаётся утверждением.

**`pdf.go:800`, дословно:** «When a PDF contains more than `maxTokenScanIterations` Pages-dictionary markers and an early marker has a legible count, `scanAllOccurrences` sets `ceilingHit`, but this branch returns the early value before examining that signal. A later marker can belong to the current incremental revision and carry a different count, so the response publishes a stale `page_count` with complete coverage even though the scan stopped early; handle `ceilingHit` before accepting `found`.»

**`media.go:575`, дословно:** «If `Info` contains `Duration` before 512 filler elements and a non-default `TimestampScale` after them, this lookup exhausts `maxEBMLElements` but discards `ceilingHit`; the separate Duration lookup succeeds, and the analyzer computes and publishes a duration using the default scale. The default is valid only when the element is known to be absent, not when its search stopped early, so this path must return an unknown ceiling result instead of an incorrect duration.»

Обратить внимание на общую форму обоих: **значение по умолчанию законно только когда элемент точно отсутствует, а не когда его поиск прервался.** Это ровно то же рассуждение, что отличает `clean` от `unknown`, применённое к характеристикам вместо проверок.

**`pdf.go:543`, дословно:** «The new literal/hex-string filter silently stops after 4096 delimiters. A fully buffered PDF with 4096 harmless strings followed by `(documentation says /JS)` leaves the final string unmarked, so `scanTokenOccurrences` treats `/JS` as dictionary syntax and emits a critical JavaScript finding—the false-positive class the new filter was intended to close.»

Здесь исчерпание делает НЕПОЛНЫМ сам набор опаковых диапазонов, то есть портит вход другого сканера. Недостаточно отметить полноту — затронутые проверки обязаны опуститься до `unknown`, потому что фильтр, работавший на неполном наборе, не имеет права ни подтвердить находку, ни объявить чисто.

**`container.go:497` — отдельный случай, сигнал не производится вовсе, дословно:** «For a ZIP entry declaring exactly `maxRelsPartBytes` but decompressing to more data, `io.LimitReader` returns exactly the allowed prefix with no error because it never asks the ZIP reader for the next byte. This function then reports the sheet count from that prefix as complete, so sheets located after 256 KiB are silently omitted; read one extra byte or otherwise verify EOF before returning `ok=true`.»

Это ловушка стандартной библиотеки: `io.LimitReader` на границе отдаёт EOF, неотличимый от настоящего. Починить здесь и **проверить каждое другое место в `internal/inspect`, где `io.LimitReader` или эквивалентная граница используется для чтения до конца** — если таких мест больше одного, они все имеют ту же дыру. Перечислить их в SUMMARY, даже если дыра нашлась только в одном.
