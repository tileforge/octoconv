# Quick Task 260817-j58

Close the Codex review finding raised on PR #9 against commit `9f54ed0`
(`internal/inspect/container.go:894`, P2), verbatim:

> When a fully read part contains a second top-level element,
> `encoding/xml.Decoder` accepts it as another element in the token stream
> rather than rejecting it as a second document root, and this EOF path still
> returns `ok=true`. For example,
> `<workbook><sheets><sheet/></sheets></workbook><ext><sheets><sheet/></sheets></ext>`
> publishes `sheet_count: 2` with complete coverage even though the workbook
> XML is not well-formed; require exactly one top-level root and reject any
> start element encountered after that root closes.

## Ground truth (measured, not predicted)

Probed against the real `encoding/xml` (Go 1.26.4) before designing the fix,
because the previous rounds of this same review were lost to reasoning ABOUT
the parser instead of asking it:

| document | bare `Token()` loop | `xml.Unmarshal` | `Decode` + require EOF |
|---|---|---|---|
| one root | ok, 1 top-level | ok | ok |
| second root element | ok, **2 top-level** | **ok** | rejects |
| non-whitespace text after root | ok | **ok** | rejects |
| whitespace / comment / PI after root | ok | ok | ok |
| prolog / comment / PI / DOCTYPE before root | ok | ok | ok |
| non-whitespace text **before** root | ok | **ok** | **ok** |
| truncated mid-tag, mismatched end tag | syntax error | syntax error | syntax error |
| empty / whitespace-only / declaration-only | ok, 0 top-level | EOF error | EOF error |

Two consequences that decide the implementation:

1. **`xml.Unmarshal` cannot be used as the oracle.** It accepts multiple
   roots and trailing text just as the raw `Token()` loop does, so
   "delegate well-formedness to the stdlib" is not available — the root count
   has to be tracked by this function itself.
2. **Character data outside the root is caught by nothing in the stdlib**
   (leading text is accepted even by `Decode`+EOF). It is equally not
   well-formed XML, so it belongs in the same fix rather than in a later
   round of the same finding.

## Tasks

### T1 — Differential test first (RED)

Files: `internal/inspect/container_test.go`

- `TestAnalyzeContainerMultipleTopLevelElementsPublishNoSheetCount` — the
  reviewer's own document, plus three roots, non-whitespace text after the
  root, and CDATA after the root: `sheet_count` must be absent/nil.
- `TestAnalyzeContainerSingleRootWithLegalSurroundingsStillCounts` — prolog,
  comment, PI, DOCTYPE and trailing whitespace/comment/PI around a single
  root must still publish the real count. Guards against over-rejection.
- `TestEncodingXMLLenienceOnMultipleRoots` — pins the measured stdlib
  behavior above (both `Token()` and `xml.Unmarshal` accept a second root).
  If a future Go release changes that, this test says so instead of the fix
  silently becoming redundant.

Verify: `go test ./internal/inspect/` fails on the new cases before T2.

### T2 — Fix the class (GREEN)

Files: `internal/inspect/container.go`

In `countSheetElements`, enforce "exactly one document root, and nothing
outside it but the prolog, whitespace, comments and PIs":

- track `rootClosed` — set when `depth` returns to 0 on an `EndElement`;
- any `StartElement` seen while `rootClosed` → `return 0, false`;
- any non-whitespace `CharData` at `depth == 0` (before OR after the root)
  → `return 0, false`.

`ok=false`, never a count: the caller already turns that into
`unknown/malformed_input` rather than publishing a fabricated
`sheet_count` with complete coverage.

Verify: `go build ./... && go vet ./... && go test ./...` all clean.
