REF = `cgr.dev/chainguard/minio@sha256:fa23f6a6f62645654530ff94aa077d1cc0d0e44c8f1cce02ab039873612edc72`

Решение планировщика (на его усмотрение, digest тот, что назвал оркестратор): форма `репозиторий@sha256:…` БЕЗ `:latest`. Оркестратор записал `…:latest@sha256:…` — тот же digest, те же байты; но chart прямо запрещает `:latest` (D-02, ловушка OrbStack с повторным pull), а парсер имён образов Kubernetes читает `:latest@digest` как тег latest при выборе pull policy по умолчанию. Одна форма в обоих файлах — чтобы гейт сравнивал строки, а не семантику.

Образ chainguard содержит minio, mc и sh в ОДНОМ образе (отдельного mc-образа нет), entrypoint `/usr/bin/minio`, пользователь 65532 (nonroot) — всё это executor перемеряет на реальном образе, а не берёт из плана.
