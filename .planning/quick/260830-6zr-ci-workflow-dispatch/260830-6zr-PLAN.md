<objective>
Перестать тратить минуты GitHub Actions на каждый пуш и каждый PR, не удаляя пайплайн и не теряя возможности запустить его вручную.

`.github/workflows/ci.yml` объявляет `on: [push, pull_request]` — то есть срабатывает дважды за цикл «запушил ветку → открыл PR». Лимиты аккаунта на исходе, гейты фаз прогоняются локально.
Output: воркфлоу, который не запускается сам, но запускается по кнопке; одна строка для отката.
</objective>

  <read_first>
    - .github/workflows/ci.yml строки 1-10 — блок `on:` и `concurrency:`; последний использует `github.ref`, который при `workflow_dispatch` по-прежнему определён, поэтому группу трогать не нужно
  </read_first>
  <action>
Строку `on: [push, pull_request]` закомментировать (не удалить) и добавить рядом `on: workflow_dispatch`.

Удалять `on:` целиком нельзя: ключ обязателен, и без него GitHub пометит файл как невалидный воркфлоу — это не тише, чем лишний прогон, это шум другого рода. `workflow_dispatch` оставляет кнопку «Run workflow» в UI и возможность запустить через `gh workflow run ci.yml`.

Рядом — комментарий из трёх фактов, чтобы следующий читатель (включая меня через месяц) не гадал: почему выключено, чем заменено локально, и что вернуть строку — единственное действие для отката. Дату поставить: причина временная, и без даты она через полгода будет выглядеть как решение.
  </action>
  <verify>python3 -c "import yaml,sys; d=yaml.safe_load(open('.github/workflows/ci.yml')); print('parses; on =', d.get(True, d.get('on')))"</verify>
