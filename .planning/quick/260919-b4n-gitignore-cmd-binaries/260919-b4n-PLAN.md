<objective>
`go build -o api ./cmd/api` кладёт бинарник в корень репозитория, и `.gitignore`
его не знает. Сейчас в корне лежат два таких: `api` (39 МБ) и `manage-clients`
(14 МБ) — 54 МБ, один `git add -A` от того, чтобы попасть в историю навсегда.

Это уже случалось: в `.gitignore` есть строка `/tectonic-worker` — ровно одно
имя, добавленное после ровно одного инцидента. Починен экземпляр, не класс:
следующий `cmd/`, собранный в корень, повторит то же самое.

Output: `.gitignore`, покрывающий бинарник каждого `cmd/*`, и тест, который не
даёт списку разойтись с `cmd/` — как `readme_sync_test.go` не даёт разойтись
списку классов движков.
</objective>

  <action>
`.gitignore`: блок между маркерами, перечисляющий `/<имя>` для каждого каталога
в `cmd/`. Маркер нужен, чтобы тест знал, где именно смотреть, и чтобы следующий
редактор видел, что строки под тестом.

Тест в новом пакете `internal/repohygiene` (пакет из одних тест-файлов —
проверено, `go build`/`vet`/`test` такой пакет принимают): сверяет множество
имён в блоке с `ls cmd/` в ОБЕ стороны. Имя в `.gitignore`, которого нет в
`cmd/` — это мусор, который однажды скроет настоящий файл; имя в `cmd/`,
которого нет в `.gitignore` — это сегодняшний дефект.

Сами бинарники не удалять: они пересобираемы, но это файлы пользователя, а не
мои. `.vscode/` и `octoconv.code-workspace` не трогать — решение, коммитить ли
настройки редактора, принимает владелец репозитория.
  </action>

    - Тест падает при добавлении имени, которого нет в `cmd/` (инверсия)
    - `/bin/` и прочие правила не тронуты
    - `go build ./...` и `go vet ./...` зелёные с новым пакетом
  </acceptance_criteria>
