<objective>
Replace five inconsistent boolean-env reads with one strict, shared, tested parser, and
sync the three documents that assert the old parsing rule. Then close two smaller
CodeRabbit findings from the same review: a stale `Error` schema description in
`docs/openapi.yaml`, and four planning documents that no longer match the repository.

Purpose: today the project's five boolean env vars parse three different ways. Four use a
raw `os.Getenv(...) == "true"` comparison, which means the inline comments that
`.env.example` itself documents on three of those four lines silently defeat the flag —
copy line 42, flip it to `WEBHOOK_ALLOW_PRIVATE_IPS=true   # for staging`, and the flag
stays OFF. The one boolean that IS lenient is `QUOTA_ENFORCEMENT_DISABLED`, which goes
through `firstField`, so `"true anything"` disables quota enforcement service-wide. That
asymmetry is exactly backwards: leniency sits on the safety control and strictness sits on
the opt-ins. One parser fixes both directions at once.

Output: a new `internal/envcfg` package with a table-driven test, five rewired call sites
with call-site tests, three synced documentation sites, one openapi description, and four
corrected planning documents.
</objective>

<deployment_risk>
**Read this before executing. It must also appear in the SUMMARY.**

Two of the five sites are security opt-ins whose effective value CHANGES for some
configurations after this task:

| If a live environment currently has | Today | After this change |
|---|---|---|
| `WEBHOOK_ALLOW_PRIVATE_IPS=true   # comment` | flag OFF (comment defeats it) | **flag ON** — RFC1918 callback targets accepted |
| `WEBHOOK_ALLOW_INSECURE_HTTP=true   # comment` | flag OFF | **flag ON** — plain-http callback URLs accepted |
| `QUOTA_ENFORCEMENT_DISABLED=true anything` | enforcement DISABLED | **enforcement ON** (unrecognized → default) |
| `S3_USE_SSL=TRUE` / `=1` / `=yes` | silently false | **process refuses to start** with an explicit error |

The first two rows are the ones that matter: a flag that is off today turns on. This is
the intended fix (the operator wrote `true` and meant `true`), and the operator has
accepted it — but it is a real posture change, not a no-op refactor. Every deployed value
in this repository is already a bare `true`/`false` (`docker-compose.yml` sets
`S3_USE_SSL: "false"` at all ten services; `deploy/chart/octoconv/values.yaml:26` sets
`useSSL: "false"`; `.env.example` sets bare booleans on all four declarations), so no
in-repo configuration changes behavior. The risk is confined to hand-edited environments
outside this repository.
</deployment_risk>

<design_decisions>
Resolved here, not left to the executor.

**D-1 — the helper lives in a new `internal/envcfg` package, and it never logs.**
Three of the five sites are in `internal/`, where CLAUDE.md states library code returns
errors and does not log. A logging parser is therefore not shareable. `internal/envcfg`
depends only on `os` and `strings`, so both `internal/api` and `internal/storage` can
import it with no cycle. `internal/api/handlers.go:8` does import `"log"` today — that is
a pre-existing inconsistency with the stated convention, it is **not** treated as licence
to widen it, and this task adds no logging to `internal/` anywhere.

**D-2 — the parser returns `(value, recognized)`; the caller decides how to surface it.**
`recognized` is false only when a non-empty raw value fails to parse. Empty/absent returns
the caller's default with `recognized == true`, because absence is legal configuration,
not a mistake.

**D-3 — surfacing is per-process-start, never per-request.** This is the constraint that
rules out the obvious designs. `internal/api/callbackurl.go:29` runs on every request
carrying a `callback_url` and `:78` runs per resolved IP per request — anything that
emits output from there floods the log on a single operator typo. So:

| Site | Reads at | Unrecognized value is |
|---|---|---|
| `internal/api/callbackurl.go:29` (`WEBHOOK_ALLOW_INSECURE_HTTP`) | per request | silently defaulted to `false` (fail-closed); surfaced by cmd/api at startup |
| `internal/api/callbackurl.go:78` (`WEBHOOK_ALLOW_PRIVATE_IPS`) | per request | silently defaulted to `false` (fail-closed); surfaced by cmd/api at startup |
| `internal/storage/storage.go:30` (`S3_USE_SSL`) | startup only | **returned as an error** — internal/ surfaces via error, every caller already `log.Fatalf`s |
| `cmd/api/main.go:185` (`QUOTA_ENFORCEMENT_DISABLED`) | startup only | logged as a warning; enforcement stays ON |
| `cmd/api/main.go:123` (`WEBHOOK_ALLOW_PRIVATE_IPS`) | startup only | logged as a warning |

`cmd/api` is the ONLY process that reads either `WEBHOOK_ALLOW_*` var (`.env.example:38-40`
states this, and grep confirms `cmd/webhook-worker` does not), so a single startup
validation block there covers both per-request sites completely. `S3_USE_SSL` gets the
error treatment instead because `storage.New` is called by ten different `cmd/*` mains —
an error is one edit that reaches all of them, whereas a warning would need ten.

**D-4 — the two webhook opt-ins both get a startup "this is relaxed" warning.** D-04 in
`cmd/api/main.go:119-125` already established that a relaxed SSRF posture must be visible
in the logs; `WEBHOOK_ALLOW_INSECURE_HTTP` was simply never given the same treatment.
Mirroring it is two lines and is a deliberate, recorded widening — not incidental scope.

**D-5 — `firstField` is untouched.** It stays exactly as it is, serving its ~28 numeric
and duration call sites, which are its designed purpose. `ParseBool` deliberately does
NOT reuse it: `firstField` splits at the first space, which would accept
`QUOTA_ENFORCEMENT_DISABLED="true anything"` as `true` — the precise defect being closed.
</design_decisions>

<behavior_table>
The contract `ParseBool` must satisfy. Every row is a required test case.

| raw value | value | recognized |
|---|---|---|
| `""` (or var absent) | caller's default | true |
| `true` | true | true |
| `false` | false | true |
| `true   # reason` | true | true |
| `false # reason` | false | true |
| `"true "` (trailing space) | true | true |
| `"  true"` (leading space) | true | true |
| `true anything` | caller's default | **false** |
| `TRUE` | caller's default | **false** |
| `1` | caller's default | **false** |
| `yes` | caller's default | **false** |
| `# only a comment` | caller's default | true (strips to empty = absent) |

Algorithm: truncate at the first `#`, `strings.TrimSpace`, then switch on exactly
`""` / `"true"` / `"false"`; anything else is unrecognized.
</behavior_table>

```go
// internal/envcfg/bool.go
package envcfg

// ParseBool interprets raw as a strict boolean flag. It returns def together
// with recognized == false when raw is non-empty but is not exactly "true" or
// "false" after stripping an inline "#" comment and surrounding whitespace.
func ParseBool(raw string, def bool) (value bool, recognized bool)

// Bool reads key from the process environment and parses it with ParseBool.
func Bool(key string, def bool) (value bool, recognized bool)
```
