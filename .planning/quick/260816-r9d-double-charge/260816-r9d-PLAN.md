**Замечание (`media.go:337`), дословно:** «When an MP4/MOV/M4A window is read successfully, this new call charges the actual bytes to `tr`, but the production dispatcher captured the original `maxBytes := tr.Remaining()` and still unconditionally calls `tr.Consume(maxBytes)` at `internal/api/inspect_handlers.go:1046`. Consequently, any nonempty ISO-BMFF read makes the second charge exceed the budget, so `BuildReport` marks even a valid, fully parsed file as partial with `work_ceiling_bytes`; either remove the per-window charge or change the dispatcher to charge only the unspent allowance.»

**Воспроизведено оркестратором через настоящий обработчик, дословный вывод:**

```
coverage.complete=false reason="work_ceiling_bytes"
REPRODUCED: a small valid mp4 reports partial coverage, reason="work_ceiling_bytes"
```

То есть КАЖДАЯ инспекция валидного MP4 сейчас врёт о своём покрытии. Замечание восьмого круга про учёт прочитанного было верным, а его исполнение создало регрессию, потому что в системе оказалось два независимых места, списывающих один бюджет.

Выбрать ОДНО место ответственности за списание и обосновать выбор комментарием. Двойной учёт — это не «лишняя строка», а отсутствие владельца у ресурса; правка обязана назвать владельца, а не просто убрать одно из двух списаний.

**Ключевое требование к тесту.** Регрессия прошла мимо всего набора, потому что тесты `internal/inspect` передают трекер напрямую, а диспетчер их не касается. Тест обязан идти через HTTP-обработчик и проверять поле покрытия в ответе — иначе он снова не поймает этот класс. Покрыть так же и остальные семейства форматов, чтобы вопрос «а не врёт ли покрытие для валидного файла» был закрыт не только для MP4.

**Замечание (`docsniff.go:120`), дословно:** «If `zip.NewReader` reads the central directory successfully but the later `readBounded` call for an ODF/EPUB `mimetype` entry encounters a non-EOF `ReadAt` failure, this recorder sets `rr.failed` only after the sole check at lines 121–135 has passed. Тот же класс, что чинился прошлым кругом, на один вызов позже: запись об отказе ведётся, но её перестают читать. Проверять признак отказа надо там, где принимается решение о возврате, а не однажды по пути.
