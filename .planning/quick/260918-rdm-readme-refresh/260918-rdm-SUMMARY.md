## Круг 1 — codex (PR #24)

Два замечания P2, оба подтверждены проверкой кода, оба оказались шире, чем названы.

**1. Таблица движков скрывала часть sanitize.** Я написал «`pdf` и шесть OOXML».
`sanitizeFormats` (`internal/convert/sanitize.go:70-93`) содержит ещё `jpg` и `png`.
Вместо правки одной ячейки выгрузил **весь** реестр через временный тест
(`LookupOp` по обеим операциям на 41 формате) и сверил все девять строк таблицы
с (operation, from, to). Нашлась вторая неточность в той же ячейке, которую codex
не называл: `docm`/`xlsm`/`pptm` не «rebuilt in place» — они пересобираются в
`docx`/`xlsx`/`pptx`, то есть меняют расширение. Остальные восемь строк сошлись
дословно.

**2. «Full contract» было ложью про `docs/openapi.yaml`.** Спека объявляла 10
путей, роутер регистрирует 12: `GET /v1/jobs/{id}/events` и
`POST /v1/jobs/{id}/cancel` отсутствовали. Это тот же класс, что и список
классов движков в README, — документ без теста, который дрейфует молча.

Поэтому закрыто классом, а не двумя вставками:

- `internal/api/openapi_paths_sync_test.go` — держит множество операций спеки
  равным множеству, которое отдаёт `chi.Walk` по **живому роутеру**
  (`Routes()` + `HealthRoutes()`), в обе стороны, с методами, а не только путями.
  Источник истины — роутер, а не регексп по `routes.go`: маршрут доходит до
  клиента только будучи зарегистрированным.
- Тест сразу нашёл **третий** дрейф, которого в замечаниях не было:
  `GET /v1/jobs` (список джоб) тоже не был в спеке — path item `/v1/jobs`
  объявлял только `post`.
- Все три операции написаны в спеку по фактическому поведению хендлеров
  (`handleJobEvents`, `handleCancelJob`, `handleListJobs`): коды, тела, заголовки
  SSE, идемпотентный 200 у cancel, клампинг `limit` вместо 422.
- `info.description` самой спеки перечисляла четыре движка из девяти — та же
  болезнь, что лечил этот PR в README. Заменена отсылкой к `GET /v1/formats`.

**Инверсия.** Тест проверен в обе стороны: удаление `/v1/jobs/{id}/cancel` из
спеки даёт `served but undocumented: [POST /v1/jobs/{id}/cancel]`; добавление
несуществующего `/v1/ghost` даёт `documented but not served: [GET /v1/ghost]`.
После восстановления файла — зелёный, `git diff` спеки содержит только
намеренные правки.
