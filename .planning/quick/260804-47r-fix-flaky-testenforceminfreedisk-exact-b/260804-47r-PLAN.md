<objective>
Fix the flaky `TestEnforceMinFreeDisk/exact_boundary_passes` subtest in `internal/convert`, which fails roughly 1 run in 5 under concurrent disk write load.

Purpose: The subtest samples free space via its own `unix.Statfs` call, then passes that stale number to `EnforceMinFreeDisk` as `inputSizeBytes` with `safetyFactor` 1.0. The guard performs its **own** `unix.Statfs` moments later and compares that fresh reading against `needed` (== the test's stale sample). Any concurrent writer — and this repo's suite runs against a live Postgres + MinIO Docker stack, both writing continuously — can shrink free space by a few KB in the window between the two syscalls, and the guard then correctly reports insufficiency. Observed failure: `free=19726426112 needed=19726434304`, a gap of 8192 bytes = 2 filesystem blocks. The subtest's name promises an *exact* boundary; what it actually constructs is "boundary as of syscall A" checked against "boundary as of syscall B". Zero slack by construction — that is the defect.

This is pre-existing and unrelated to open PR #5: `git diff --name-only origin/main..HEAD -- internal/convert/avdiskguard*.go` is empty. A sibling subtest in the same file was already de-flaked once for the mirror-image reason (commit `7c308ec`), which fixed the *insufficient* case by demanding an unsatisfiable 1 PiB — slack the boundary case cannot have.

Output: A test-side fix that makes the boundary assertion deterministic, with the production guard's fail-closed strictness left untouched.
</objective>

  <behavior>
    Deterministic assertions to write FIRST, against the new pure decision helper (no syscall, no temp dir, no skip-on-zero-free guard):
    - Exact boundary: free equal to needed returns nil. Use a test-owned constant free value and derive inputSizeBytes from it with safetyFactor 1.0, so equality holds by construction rather than by two syscalls agreeing.
    - One byte below the boundary: free one less than needed returns a non-nil error satisfying errors.Is against ErrAVInsufficientDiskSpace. This is what actually pins the comparison as strict — without it, the boundary case alone cannot distinguish `<` from `<=`.
    - Above the boundary: free comfortably greater than needed returns nil.
    - Zero-free host: free of 0 with needed of 0 returns nil (the degenerate equality), free of 0 with any positive needed returns the sentinel error. This replaces the three `t.Skip("host reports zero free bytes")` escapes with real coverage rather than silently skipping.
    - Error text: the insufficient-space error string still carries free, needed, input and factor values (the format contract downstream operators read in logs).

    Retained live-filesystem behaviors (must keep passing unchanged):
    - Sufficient space passes: `EnforceMinFreeDisk(dir, 1, 3.0)` returns nil.
    - Insufficient space fails closed: `EnforceMinFreeDisk(dir, int64(free), 2.0)` returns the sentinel — assertions untouched per D-02.
    - Statfs error on a bogus path returns a wrapped statfs error that is NOT the insufficient-space sentinel.
