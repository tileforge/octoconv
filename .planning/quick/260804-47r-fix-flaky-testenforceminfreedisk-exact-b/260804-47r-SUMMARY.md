# Quick Task 260804-47r: Fix flaky TestEnforceMinFreeDisk/exact_boundary_passes Summary

**Split `EnforceMinFreeDisk` into a live `unix.Statfs` read plus a pure unexported `checkFreeAgainstNeeded` decision helper, so the exact-boundary test asserts `free==needed` against a test-owned constant instead of racing two independent syscalls under concurrent disk load.**

## Accomplishments

- Reproduced the pre-existing flake live on the unfixed code before touching anything (AC-0), proving the load harness has teeth rather than assuming the bug report was accurate.
- Split `EnforceMinFreeDisk` into the unchanged live-`unix.Statfs` read plus a new pure, unexported `checkFreeAgainstNeeded(free uint64, inputSizeBytes int64, safetyFactor float64) error` holding the strict `free < needed` decision verbatim (same computation, same `%w` wrap, same error format string).
- Rewrote the exact-boundary subtest to call `checkFreeAgainstNeeded` directly with a test-owned `1<<30` (1 GiB) constant — `free == needed` now holds by construction, not by two `Statfs` calls agreeing within a race window.
- Added the previously-missing one-byte-below-boundary subtest, which is what actually proves the comparison is `<` and not `<=` (the exact-boundary case alone can't distinguish the two).
- Replaced the three `t.Skip("host reports zero free bytes")` escapes on the boundary path with real zero-free-host coverage (`free=0, needed=0` passes; `free=0, needed>0` fails closed) plus an explicit error-text assertion.
- Kept "insufficient space fails closed", the bogus-path statfs-error subtest, and the `errors.Is` unsatisfiable-1PiB subtest completely untouched (D-02).
