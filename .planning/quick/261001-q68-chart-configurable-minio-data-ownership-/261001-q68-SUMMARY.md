## Deviations / planner decisions

1. **Explicit `runAsGroup: 0` on the init container.** Without it the pod-level `runAsGroup` would apply to the init container and its measured 0:0 identity would silently become 0:65532. The ncn summary now checks `group=0`; inversion (vi) proves the gate sees it.
2. **migrate is validated at render time (added at discretion).** `--set ...migrate=no` gives the string `"no"`, which is truthy in `if`, so the init container would stay silently. It is the same class of silent coercion that the uid/gid check closes for numbers; the check is outside the condition, so it also runs with migrate=false.
3. **YAML parser in the guard test, `go.yaml.in/yaml/v3` direct.** The key is just `image:`; a line regex cannot tell it from `minio.image` or `prometheus.image`. The module was already in the graph (v3.0.5 through pdfcpu) and in go.sum, so `go mod tidy` only flips the `// indirect` marker. `git diff a7ce8b4 HEAD -- go.sum` is empty and `go mod tidy -diff` is empty.
4. **`--from=0` unchanged, and the boundary it implies.** Changing `uid` on a volume that already belongs to another uid (for example 65532 after an earlier migration) does not rewrite it. Measured by the custom probe (`already-65532` and `already-target` untouched, ctime and inode included) and documented in `values.yaml`. uid 0 is accepted (non-negative), no special rule.
5. **Probe detail.** In the probe the init identity is built from the container securityContext with a fallback to the pod; the render pins 0:0, and the probe fails if it is anything else. The server container in the probe runs with the pod identity from the render (`-u runAsUser:runAsGroup --group-add fsGroup`), not with the image `USER`, so the custom run really exercises uid 1000.
6. **Plan verify command defect (Task 1).** The literal `S="$(... | grep -v '^---$')"` comparison cannot pass: yq prints empty lines for the documents that `select` skips (the PVC before the Deployment), so `$S` carries leading blank lines. With `grep -v '^$'` added the value is exactly `1000 2000 2000 0 0 1000:2000`. The same check is covered by the ci-helm-checks section, which is stricter. Nothing in the chart was changed because of it. A related effect in the Task 2 verify did not occur.
7. **Inversion (iv) first failure.** With the kind check removed, the first failing value in the invalid-values section is `uid=1.5` (a string that `int64` coerces to 0), not `abc`; both are strings.

## PR body addendum (round 2) - English paragraph for PR #31

> **Addendum, round 2: MinIO data ownership is configurable.** The init container that hands root-owned MinIO data to uid 65532 reused `minio.image` and hard-coded 65532:65532. An operator who swapped `minio.image` for an image without GNU `chown` got a pod stuck in Init, and one who ran MinIO as another uid got a volume owned by the wrong user. Three new values, with defaults that keep today's behavior:
> - `minio.dataOwnership.uid` / `gid` (65532): the single source of `runAsUser`, `runAsGroup` and `fsGroup` of the MinIO pod and of the owner the init container hands the volume to, so the pod and the volume cannot drift apart. The pod used to rely on the image's `USER`, so the identity is now set explicitly; at the defaults the rendered pod differs from before by exactly three lines (`runAsUser: 65532`, `runAsGroup: 65532` on the pod, `runAsGroup: 0` on the init container) and the effective identity is the same. The init container pins `runAsGroup: 0` because the pod-level `runAsGroup` would otherwise turn its 0:0 into 0:65532.
> - `minio.dataOwnership.migrate` (true): `false` renders no init container at all, for a volume the old image never wrote or whose ownership is managed outside the chart.
> - `minio.dataOwnership.image` (empty, falls back to `minio.image`): image of the init container only; the server and every `mc` container keep their own. A non-empty value in the repository's values files must be `name@sha256:<64 hex>` with no tag.
>
> Wrong values fail `helm template` instead of a pod: uid and gid must be whole non-negative numbers (checked on the raw value before any conversion, so `abc`, `1.5`, `"1000"`, `true`, `null`, `1000:0`, `-1` and a missing block abort and name the key; the output goes through `printf "%d"` because 1000000 from a values file would otherwise print as `1e+06`), and `migrate` must be a boolean (the string `no` is truthy in a template condition and would have kept the init container silently), including when `migrate` is `false`. `--from=0` is unchanged, so changing the uid does not rewrite a volume that already belongs to another uid (for example 65532 after an earlier migration); this is documented in `values.yaml`.
>
> **How it was checked.** Render gates in `scripts/ci-helm-checks.sh`: the default shape; uid 1000 / gid 2000 through `--set` and 1000000 / 1000001 through a values file, where the pod identity and the chown target move together and the whole-chart diff is exactly eight lines; `migrate=false` against the default render with only the MinIO `initContainers` key removed (byte-equal); a custom image changes exactly one rendered line and reaches only the init container; every invalid value above aborts. Each new gate was inverted once and failed. `TestMinioImagePinnedByDigest` now accepts exactly three `image:` forms with `.Values.minio.*` and finds `minio.dataOwnership.image` with a YAML parser (a line regex cannot tell it from `minio.image`; `go.yaml.in/yaml/v3` was already in the module graph and go.sum is unchanged), and a mirror with `minio` in its name under that key is not mistaken for the server image. The rendered pod was run under docker (all flags from the render) in two modes: the defaults reproduce the previous result, and with uid 1000 / gid 1001 the volume is handed to 1000:1001, MinIO started as 1000:1001 is ready, serves the old object byte-for-byte and accepts a write, while files already owned by 65532 or another uid stay untouched. `scripts/ci-local.sh helm gate`: helm PASS, gate PASS on the PR head.
>
> **Not verified:** a live cluster (Kubernetes was off), amd64, a custom `minio.dataOwnership.image` beyond rendering, and MinIO images other than the pinned one under their own uid.
