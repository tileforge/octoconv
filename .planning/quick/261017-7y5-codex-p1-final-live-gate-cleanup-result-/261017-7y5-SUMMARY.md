# Quick 261017-7y5: a failed cleanup in the final gate wrapper fails its step Summary

**Complete, against stubs only.** A failed cad cleanup, or a command failure hidden behind `|| true` that a
verdict reads, can no longer end in `SUMMARY,result=ALL PASS`. The 76-11 gate verdict is unaffected: attempt 4's
cad cleanup recorded `result=ok` (evidence/76-11-final-gate.txt line 44). The live gate was not rerun.

`commits: 4` and `plan_head_after` cover the code/test commits. The docs commit for this SUMMARY and the STATE
commit come after it.

## The finding and the fix

Codex P1 on PR #37: `cad_cleanup` writes `result=fail` into its CLEANUP line but always returns 0, because its last
command is `ev`. `run_cad` called it with the status unchecked, both on the normal path and on the STOPPED path. So a
failed DB query, an id that is not a UUID or a failed MinIO deletion still let `run_cad` return 0, and the gate
reported ALL PASS. The suite's "bad job id" case asserted only the CLEANUP line, and on the base code it reached
ALL PASS.

The fix (cbea783):
- `cad_cleanup` ends with `[ "$res" = ok ]`.
- `run_cad` captures the status: `cad_cleanup "$since" "$n" || crc=$?`. A non-zero status gives `cres=fail` and `ok=0`.

CAD_RUN before and after:

```
before  CAD_RUN,run=1,rc=0,all_pass=1,tracked_dirt=0,commit=<c>,commit_match=1,transcript=76-11-liveproof.txt,result=ok
after   CAD_RUN,run=1,rc=0,all_pass=1,tracked_dirt=0,commit=<c>,commit_match=1,cleanup=ok,transcript=76-11-liveproof.txt,result=ok
        CAD_RUN,run=1,rc=0,all_pass=1,...,cleanup=fail,transcript=76-11-liveproof.txt,result=fail
STOPPED (no CAD_RUN line before)
        CAD_RUN,run=1,rc=<rc>,cleanup=ok|fail,transcript=76-11-liveproof.txt,result=not_run,reason=stopped_terminated|stopped_vm_disk
        CAD_RUN,run=1,rc=<rc>,cleanup=not_run,transcript=76-11-liveproof.txt,result=not_run,reason=stopped_docker_unresponsive
```

The STOPPED contract is kept. `run_cad` still returns 2, the cad STEP is NOT_RUN and the SUMMARY is INCOMPLETE, and
a failed cleanup during a stop is recorded but does not turn the stop into FAIL. When docker is unresponsive no
cleanup is attempted, as before. step_cad is unchanged: a non-zero `r` already became STEP_RC=1 and return 1.

## Deviations from Plan

**1. [Rule 3 - Blocking] macOS `mktemp -d` does not honour TMPDIR.**
- **Found during:** Task 1 RED, the docker-unresponsive case.
- **Issue:** I measured it: `TMPDIR=X mktemp -d` still creates the directory under DARWIN_USER_TEMP_DIR
  (`/var/folders/.../T`). So `run_wrapper_term` found no directory under its TMPDIR, and the stop file went to `/stop`.
- **Fix:** a `mktemp` stub in `$STUB`. Its real path is captured with `command -v mktemp`. For exactly `-d`, with
  `STUB_TMPDIR` set, it creates `$STUB_TMPDIR/tmp.XXXXXXXX`; otherwise it execs the real mktemp. `run_wrapper_term`
  sets both TMPDIR and STUB_TMPDIR. The change is test-only.
- **Commit:** 9497aae.
