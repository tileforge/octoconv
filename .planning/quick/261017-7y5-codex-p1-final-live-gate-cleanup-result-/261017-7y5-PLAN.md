# Quick 261017-7y5: a failed cleanup in the final gate wrapper fails its step

## Objective

Codex P1 on PR #37 (branch `gsd/phase-76-measured-bounds-keda-proof-client-docs`). In
`scripts/final-live-gate.sh`, `cad_cleanup` (lines 465-508) writes `result=fail` into its CLEANUP line
but always returns 0, because its last command is `ev`. `run_cad` (lines 519-543) calls it with the
status unchecked, on both the normal path (line 529) and the STOPPED path (line 526). So a failed DB
query, an id that is not a UUID, or a failed MinIO deletion still lets `run_cad` return 0, and the gate
reports `SUMMARY,result=ALL PASS`. The existing suite case "bad job id" (test lines 403-406) asserts
only the CLEANUP line, so this case reaches ALL PASS on the current code.

Fix it for the whole class, not just the instance Codex named:
1. **Named finding.** `cad_cleanup` returns non-zero when `res=fail`. `run_cad` folds that into `ok` and
   into a `cleanup=` field of CAD_RUN. On the STOPPED path the step still returns 2, and the cleanup
   result is recorded.
2. **Sweep, part A (verdict to return code).** Every helper in the wrapper that computes a
   result/res/ok verdict, or writes a `result=fail` line, must carry it to its step's return code. The
   same goes for this branch's `scripts/ci-local.sh` diff.
3. **Sweep, part B (failed input to verdict).** This is the same false-ALL-PASS outcome reached one step
   earlier. Some verdicts read a command whose failure is hidden by `|| true`, and an empty result then
   reads as clean. Each such site is fixed fail-closed when a non-zero exit is a reliable failure signal.
   If it is not reliable, the site is recorded with the missing information named.

Stubs only. Do not run the live gate, docker, kubectl or helm. The suites put stub docker, kubectl, lsof,
npm, go and sysctl first on PATH.
