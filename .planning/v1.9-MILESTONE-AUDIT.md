## Cross-Phase Integration (COHERENT — gsd-integration-checker)

All wiring traced end-to-end, `go build`/`go vet`/`go test` clean:
1. **Schema (38) → consumers (40/41/42):** 0007 columns written by UpdateProgress/SetSourceDuration, read by Get/handleGetJob (null-aware), surfaced in List/JobSummary + SSE snapshot + webhook body. No added-but-unused column; no consumer of a nonexistent column.
2. **Cancel (39) ↔ Progress (41):** the per-attempt cancelFn (attemptCtx) drives runCommandStreaming's SIGKILL; freeze-on-cancel is structural (UpdateProgress `WHERE status='active'` + guarded Cancel transition) — `TestProgressFreezeOnAbort` passes.
3. **Progress (41) → Push (42):** SSE (handleJobEvents) + progress webhook (fireDetached) read the same columns / share the throttle decision; fireDetached never enqueues (`TestProgressWebhookNeverEnqueues`).
4. **Route coherence:** GET /jobs, GET /jobs/{id}, GET /jobs/{id}/events, POST /jobs/{id}/cancel share the identical auth chain + byte-identical 404-not-403 ownership.
5. **Terminal vs progress webhook separation:** `event:"completed"` (terminal, bounded-retry/dead-letter) vs `event:"progress"` (best-effort, no retry) on the same callback_url, both HMAC-signed — client-distinguishable.
6. **Migration ordering:** 0007 then 0008 apply in lexical order via embed.FS; both pure-additive.
7. **E2E "submit av → SSE/webhook → optional cancel → frozen/terminal":** fully wired; cancel applies uniformly across all engine workers (shared cancel.Subscriber).
