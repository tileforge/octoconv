## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-03 | Tampering | `azure/setup-helm` in the new `helm` job | mitigate | Job declares `permissions: contents: read` — no secrets are referenced and no write scope is granted, so a compromised action cannot push, tag, publish a package, or read a token beyond read-only checkout. The action is pinned to a major tag, matching this file's four existing tag-pinned actions (introducing SHA pinning for one job while the others float on tags would be inconsistent security theatre, not a real improvement). The installed helm binary is separately pinned via the `version:` input, so chart render behavior cannot change without a commit here. Before use, confirm the action resolves to the vendor-published `Azure/setup-helm` repository and that the pinned major tag exists. Not a package-manager install, so the npm/pip/cargo Package Legitimacy Gate does not apply; no `[ASSUMED]`/`[SUS]` package is introduced anywhere in this phase. |
| T-54-04 | Denial of Service | `values-capacity-floor.yaml` applied to a real cluster | accept | Low severity, mitigated by documentation rather than code: the header comment marks the file an EXAMPLE and states that applying it permanently pins two `worker` pods. The value is `2` against `keda.image.maxReplicaCount: 4`, i.e. inside a ceiling that was already reviewed and reachable under autoscaling, so the worst case adds no capacity headroom beyond what the chart already permits. Accepted rather than mitigated further because guarding an operator against applying a values file they explicitly passed to `-f` is not something the chart can or should do. |

Not applicable to this plan, deliberately not padded: Spoofing, Repudiation, Information Disclosure
and Elevation of Privilege. This plan adds one values file containing a single integer and one CI
job that reads the repository and renders templates — no identity, no secret, no audit claim, and no
privilege boundary is introduced. Resource-exhaustion via an oversized floor is modelled as T-54-01
in plan 54-01, where the `fail` guard that bounds it lives.
