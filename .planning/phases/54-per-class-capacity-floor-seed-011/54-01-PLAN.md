<objective>
Replace the `minReplicaCount: 0` hardcoded in all seven `scaledobject-*.yaml` files with an
operator-settable Helm values field, and make `fallback.replicas` follow the floor instead of the
hardcoded `1`. Both go through a single helper family in `_helpers.tpl` (D-03), which also
fail-fast validates the value (D-02).

Purpose: CAPA-01/SEED-011 — an operator can eliminate cold-start latency on a class under
sustained load. The default stays `0`, so the current deployment's rendered manifests do not
change at all (SC1).

Output: two new `define`s in `_helpers.tpl`, seven `minReplicaCount: 0` keys in `values.yaml`,
and seven rewired ScaledObject templates whose trigger comments no longer contradict the new
fallback behavior.

Non-goals (do not touch): `internal/convert/exec.go` (project invariant, byte-for-byte
unchanged — nowhere near this phase's scope), the three existing overlays
`values-local.yaml` / `values-e2e.yaml` / `values-loadproof.yaml` (D-04), and every other KEDA
knob (`threshold`, `maxReplicaCount`, `pollingInterval`, `cooldownPeriod`,
`scaleDownStabilizationSeconds`, PromQL queries).
</objective>

New named templates in `deploy/chart/octoconv/templates/_helpers.tpl`:

- `octoconv.kedaMinReplicaCount` — call as
  `{{ include "octoconv.kedaMinReplicaCount" (dict "class" "<class>" "root" $) }}`.
  Emits the integer `.Values.keda.<class>.minReplicaCount` with no surrounding whitespace.
  Aborts the render via `fail` on a negative value or on a value greater than that class's
  `maxReplicaCount`.

- `octoconv.kedaFallbackReplicas` — same dict argument. Emits
  `max(1, .Values.keda.<class>.minReplicaCount)`, and therefore inherits the same validation
  because it computes its result from an `include` of `octoconv.kedaMinReplicaCount`.

New values key, present on all seven `keda.<class>` blocks in `values.yaml`, default `0`:
`keda.image.minReplicaCount`, `keda.document.minReplicaCount`, `keda.html.minReplicaCount`,
`keda.audio.minReplicaCount`, `keda.av.minReplicaCount`, `keda.ocr.minReplicaCount`,
`keda.pandoc.minReplicaCount`.

The seven class keys map to these template files and ScaledObject names:
`image`→`scaledobject-image.yaml`/`worker-image-scaledobject`,

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-54-01 | Denial of Service | `keda.<class>.minReplicaCount` → all 7 ScaledObjects | mitigate | D-02's `fail` guard in `octoconv.kedaMinReplicaCount` rejects any floor above that class's own `maxReplicaCount` (4 for image, 2 for the other six), so the maximum reachable pinned footprint is 16 pods — the same ceiling autoscaling could already reach under load, i.e. this phase adds no new capacity-exhaustion headroom. Negative values are rejected outright. The render aborts at `helm template`/`helm lint` time, before any cluster contact. Residual (accepted): an operator who also raises `maxReplicaCount` can raise the floor with it — that knob predates this phase and its review is unchanged. |
| T-54-02 | Tampering | `fallback.replicas` semantics under scaler failure | mitigate | Deriving `octoconv.kedaFallbackReplicas` from an `include` of `octoconv.kedaMinReplicaCount` rather than re-reading `.Values` means a floor cannot be silently undone by a Prometheus outage, and means the D-02 validation cannot be bypassed by reaching the fallback path alone. Verified by Task 2's per-file `grep -c … = 2` criterion (both call sites present in every file). |

Not applicable to this plan, deliberately not padded: Spoofing, Repudiation, Information Disclosure
and Elevation of Privilege have no surface here — this plan adds no identity, no logging claim, no
secret, and no RBAC/`securityContext` change. Package Legitimacy Gate: no npm/pip/cargo install is
