<objective>
Write the pinning tests that freeze TODAY's seven-handler behavior, BEFORE any consolidation
happens. This is step 1 of the three-step zero-behavior-change protocol (56-CONTEXT.md D-10)
and the direct countermeasure to PITFALLS.md Pitfall 14 ("the test suite proves the runner's
shape, not the seven engines' pre-existing behavior").

The seven `Handle*Convert` methods are not unit-testable today: `Handler.repo` is a concrete
`*jobs.Repo` and `Handler.enqueuer` a concrete `*queue.Client`, so constructing a `Handler`
needs a live Postgres/Redis (`internal/worker/pandoc_integration_test.go:28-38` documents this
exact limitation). Task 1 introduces the minimum behavior-preserving seams to lift that
restriction; Tasks 2 and 3 then pin the network those seams expose.

Purpose: after this plan lands, any future diff that changes a failure code, a terminal/transient
verdict, an emission order, or a metric label set for any of the seven engine classes fails
loudly in CI — and plan 56-04's refactor must make these exact tests pass WITHOUT rewriting them.
Output: a pinning suite that is treated as frozen from the moment it is committed.
</objective>
