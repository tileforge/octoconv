<objective>
Close ERRC-03 and ROADMAP SC5's consumer half: the reference frontend and both MCP servers select
behavior from the machine-readable `code`, and a test proves no consumer branches on message text.

Starting position, verified at planning time:
- `frontend/src/api.ts:36-58` — `ApiError` carries only `status` and `message`; the code field in
  the body is discarded. `App.tsx:18-38` `describeError` branches on `error.status` alone.

  pattern ERRC-03 forbids.

Both MCP entry points (`cmd/mcp-server`, `cmd/mcp-http`) are thin wrappers over
`internal/mcpserver`, so one change covers both — but both must be verified, not assumed.

Purpose: the contract frozen in plan 56-06 is actually consumed, and proven to be.
Output: code-driven consumers plus the tests that keep them honest.
</objective>
