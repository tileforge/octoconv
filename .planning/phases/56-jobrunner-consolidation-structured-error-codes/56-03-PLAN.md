<objective>
Close the synchronous half of the error-code contract: widen `internal/api`'s `writeError` to
carry a machine-readable `code` and tag all 112 call sites across the six files that use it, per
56-CONTEXT.md D-01/D-02.

This is deliberately a single atomic sweep. `writeError` is package-private to `internal/api`, so
its signature change breaks every call site in the package simultaneously — splitting the sweep
across tasks or plans would leave a non-compiling tree between commits.

Call-site inventory (verified by grep at planning time):
`handlers.go` 62, `system_presets_handlers.go` 19, `presets_handlers.go` 18, `sse.go` 4,
`system_usage_handlers.go` 5, `jobs_list_handler.go` 4.

Purpose: after this plan, a consumer can branch on `code` for every 4xx/429 the service returns,
not just the two 429s that already carry one.
Output: a fully tagged `internal/api` plus tests proving no response can escape untagged.
</objective>

| Boundary | Description |
|----------|-------------|
| client → API | Every `writeError` site is a rejection of untrusted input crossing into the service; the code is now part of the response contract |
| API → consumer (frontend, MCP) | The code becomes a machine-readable branch key; it must never carry request-derived text |
