<objective>
Wire the speed layer end to end so cancelling an active job actually kills the real
in-flight engine process (CNCL-03 mechanism). Three cohesive, atomic pieces:
  1. worker.process() registers the per-attempt cancel func in cancel.Default before Convert
     and deregisters on return; the Handle*Convert functions gain a context.Canceled arm that
     returns asynq.SkipRetry WITHOUT MarkFailed (the job is already `canceled` in Postgres).
  2. cmd/api injects a *cancel.Publisher via the SetCancelPublisher seam from Plan 01.
  3. every engine worker runs a *cancel.Subscriber against cancel.Default.
The existing hardened runCommand SIGKILL-on-ctx.Done path is reused UNCHANGED (D-04): a
registered context.WithTimeout cancel func, when called early, cancels the attempt ctx →
runCommand kills the process group → ctx.Err() is context.Canceled (distinct from the
timeout's context.DeadlineExceeded). NO exec.go change.

Purpose: Low-latency in-flight kill on top of the already-correct DB cancel.
Output: worker registration + classification, api publisher wiring, worker subscriber wiring.

Locked decisions honored: D-04 (register the per-attempt cancel func; reuse runCommand; no
exec.go change; wire into every engine worker — av/audio matter most), D-05 (allow-list is
the backstop; pub/sub is only latency), D-07 (context.Canceled → SkipRetry, no MarkFailed;
the MarkActive-rejected-because-canceled case already returns SkipRetry — leave it), D-06
(dequeue-and-drop: no DeleteTask). Do NOT touch webhook delivery (D-08).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Redis job:cancel → worker registry → runCommand ctx | A received cancel cancels a real OS process group via the hardened kill path. |
| asynq retry ← worker return value | Misclassifying a cancel could resurrect a stopped job. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-07 | Elevation/Correctness | runCommand process-group kill | mitigate | Reuse exec.go UNCHANGED (D-04) — the registered WithTimeout cancel func triggers the existing Setpgid + syscall.Kill(-pid, SIGKILL) path; `git diff exec.go` empty is an acceptance gate, guarding against the Pitfall-3 whole-group-kill regression. |
| T-39-08 | Tampering | asynq retry of a canceled task | mitigate | context.Canceled → asynq.SkipRetry with NO MarkFailed (D-07); the guarded-transition allow-list independently rejects any terminal Mark* on an already-canceled job (the authoritative backstop, Plan 04), so a missed classification still cannot resurrect the job. |
| T-39-09 | Denial of Service | subscriber goroutine per worker | mitigate | One long-lived subscriber goroutine per worker bound to the process signal ctx; Plan 02's Run returns on ctx.Done(). Plan 04's live proof asserts no goroutine growth across repeated cancels. |
| T-39-06 | Correctness | missed signal | accept | Latency-only optimization (D-05/D-12); a missed signal falls through to completion/timeout + allow-list rejection — wasted compute, never corruption. No DeleteTask (D-06), no DB re-poll (D-12). |
</threat_model>
