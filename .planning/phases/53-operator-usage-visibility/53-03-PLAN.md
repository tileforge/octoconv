<objective>
Wire the two new repo reads into `api.Server` behind narrow interfaces, and update every `NewServer` call site in the same change so the build never sits half-migrated.

Purpose: `Server` currently has no `clients` dependency at all, and `cmd/api/main.go` already constructs `clientRepo` without ever passing it to `api.NewServer`. This plan closes that gap and gives plan 53-04's handler its two dependencies. It deliberately ships NO route and NO handler — this is contract-and-wiring only, so the blast radius of the signature change is isolated from the endpoint's own logic.

Output: `internal/api/api.go`, `cmd/api/main.go`, `internal/api/handlers_test.go`, `internal/api/system_presets_handlers_test.go` (all modified).
</objective>

New `Server` fields: `usageRepo UsageRepo`, `limitsRepo LimitsRepo`.

New `NewServer` signature (the two new interfaces sit immediately after `presetAdmin`, keeping every dependency interface positional and grouped, with `Config` reserved for tunables per its existing doc convention):

```
func NewServer(
    repo Repo,
    storage Storage,
    queue Enqueuer,
    presets PresetRepo,
    presetAdmin PresetAdmin,
    usage UsageRepo,
    limits LimitsRepo,
    resolver auth.ClientResolver,
    health HealthDeps,
    cfg Config,
) *Server
```

Contracts this plan CONSUMES (delivered by plans 53-01 and 53-02 — read those files, do not redeclare):
- `jobs.UsageRow` and `func (r *jobs.Repo) UsageSummary(ctx, clientID *uuid.UUID, dayFrom, dayTo time.Time) ([]jobs.UsageRow, error)` — `internal/jobs/usage_query.go`
- `clients.LimitWithMeta` and `func (r *clients.Repo) ListAllLimits(ctx, clientID *uuid.UUID) ([]clients.LimitWithMeta, error)` — `internal/clients/limits.go`

Existing contracts this plan must not break:
- `func (s *Server) SetCancelPublisher(p CancelPublisher)` — the post-construction setter idiom (`api.go:176`). It is NOT the pattern to copy here: `cancelPublisher` is nil-safe by design (a nil publisher simply skips a best-effort publish), whereas a nil `usageRepo` would panic the endpoint. These two dependencies are load-bearing, so they are positional constructor params.
