<objective>
Fix the two read-layer defects behind the operator report's remaining trust gaps, both confined to `internal/jobs/usage_query.go`:

- **WR-01** — `jobs.client_id` is nullable with `ON DELETE SET NULL` (`internal/db/migrations/0001_init.sql:43`). Both in-flight statements `GROUP BY client_id` with no `IS NOT NULL` guard, so every job orphaned by a deleted client collapses into one `client_id = NULL` group that pgx silently scans into `uuid.Nil`. The result is a phantom client row in the operator report carrying `client_name: ""` and `enforcement_mode: ""` — a value `docs/openapi.yaml` declares as `enum: [observe, enforce]` and `required`. It manifests only on the un-narrowed shape (D-01's primary shape), because the `($1::uuid IS NULL OR client_id = $1)` bind already excludes NULLs when a `?client_id` is supplied.
- **WR-03 (repo half)** — the API resolves "today" from the API host's wall clock while `evaluate()` resolves it from Postgres `now()`. This plan adds the server-side clock read the API layer needs; plan 53-07 wires it into the handler.

Purpose: the emitted row set must be exactly the set of real clients — no real ones missing (plan 53-05), no fabricated ones present (this plan) — and both sides of the visibility/enforcement comparison must read one clock.
Output: guarded in-flight SQL, a `Repo.UTCToday` method, and DB-gated tests that pin both, plus a flake-proof `utcToday` test helper.
</objective>
