<objective>
Stop `GET /v1/system/usage` from overstating its own truth claims — the failure mode D-05 and this whole phase exist to prevent, and the one 53-VERIFICATION.md flagged against verified truths #7 and #9.

- **WR-02** — `remaining_matches_admission_gate` is set solely from `period == "today"`, and `remaining_note` asserts "remaining is exactly what the admission gate computes right now". That is false in two reachable configurations: a row whose `enforcement_mode` is `observe` (the column DEFAULT for every provisioned client — `admitLocked` computes the verdict and admits anyway), and the service-wide `QUOTA_ENFORCEMENT_DISABLED` kill-switch, whose state is currently invisible in the response entirely.
- **WR-03 (API half)** — the handler resolves "today" from `time.Now()` (the API host) while `evaluate()` resolves it from Postgres `now()`. Plan 53-06 added `jobs.Repo.UTCToday`; this plan wires it in.
- **WR-07 #1 / IN-07b** — with an injectable clock, `TestSystemUsage_DefaultPeriodIsToday`'s midnight flake disappears, and the thrice-repeated `"today"` literal collapses to one constant.

Purpose: an operator-visible number that does not match enforcement reality is worse than no number (D-05). The endpoint must say what it actually knows.
Output: an enforcement-aware envelope, a server-derived day range, and deterministic tests for both.
</objective>

<design_resolution>
## Locked semantics (do not re-litigate during execution)

`remaining_semantics` gains a third value and a fixed precedence order. Evaluate in exactly this order:

1. `period != periodToday` → `"hypothetical_single_day_equivalent"` (D-09, unchanged text). Multi-day wins over the kill-switch: the figure has no admission-gate analogue regardless of whether enforcement is live.
2. else if `s.quotaEnforcementDisabled` → `"computed_but_not_enforced"` — the arithmetic is exactly `evaluate()`'s, but no request is being rejected service-wide.
3. else → `"live_admission_gate"` (unchanged), with the note EXTENDED to state that a row whose own `enforcement_mode` is `observe` has its verdict computed and counted but never enforced.

`remaining_matches_admission_gate` = `period == periodToday && !s.quotaEnforcementDisabled`.

`quota_enforcement_disabled` is a NEW top-level boolean, always present, reporting the kill-switch independently of period — it is the only way an operator can learn this state, since no per-row field can carry it.

Per-row `enforcement_mode` stays exactly as it is: reporting the stored column is correct; do NOT rewrite it to `"observe"` when the kill-switch is on. The kill-switch is a separate, orthogonal fact and gets its own field.
</design_resolution>
