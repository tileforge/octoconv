Deliver the opt-in `progress` webhook (PUSH-02 / D-04): add an additive `event` discriminator to BOTH webhook bodies (terminal + progress), fire a best-effort single-attempt HMAC-signed progress POST inline from the Phase 41 `progressSink` — DETACHED with its own short timeout so it never blocks the ffmpeg reader goroutine, gated by the SAME PROG-03 throttle + the per-job opt-in, and structurally incapable of enqueuing to the terminal retry/dead-letter queue — and wire `cmd/av-worker` to construct a real `webhook.Deliverer` + read `WEBHOOK_SIGNING_SECRET`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| av-worker → client callback_url | worker POSTs signed progress to a client-chosen (already SSRF-validated) URL |
| ffmpeg reader goroutine → progressSink.Update | a slow/adversarial callback endpoint must not stall the transcode |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-07 | Denial of Service | slow/hanging callback_url stalling the transcode | mitigate | fireDetached fires from a short-lived DETACHED goroutine bound to its OWN context.WithTimeout — Update returns immediately regardless of endpoint latency; timeout shorter than the throttle interval self-bounds in-flight goroutines (Pitfall 5) |
| T-42-08 | Tampering / budget mixing | progress delivery leaking into the terminal retry/dead-letter queue | mitigate | No enqueue path exists in the progress path (no NewWebhookDeliverTask / enqueuer / webhookRepo reference) — separation from the terminal bounded-retry/dead-letter budget is by construction (D-04, verified by grep gate) |
| T-42-09 | Spoofing | forged progress webhook body | mitigate | Reuses the existing webhook.SignPayload HMAC-SHA256 scheme + WEBHOOK_SIGNING_SECRET; the signature covers the marshaled bytes including the `event` discriminator on both bodies (V6, unchanged crypto) |
| T-42-10 | Tampering (SSRF) | inline delivery to a re-validated/second URL | accept | The callback_url was validated ONCE at job create (Plan 01 / handleCreateJob); av-worker's inline delivery reuses that SAME stored URL and never re-validates (one validation site, two consumers — RESEARCH Open Question 3) |

No package-manager installs in this plan — no `T-42-SC` supply-chain checkpoint required.
</threat_model>
