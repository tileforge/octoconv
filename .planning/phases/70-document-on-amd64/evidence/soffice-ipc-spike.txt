== OBSERVATIONS
- M1: soffice.bin (not oosplash) binds an AF_UNIX socket at /tmp/OSL_PIPE_65534_SingleOfficeIPC_<hash> (65534 = nobody), connects to it itself, and unlinks it (unlinkat, result 0). The first soffice.bin run exits 81 after that unlink; the second binds the same path again, converts, and unlinks the path at exit. Nothing is left in /tmp afterwards, so soffice DOES unlink its socket at exit (with the rights of an unconfined nobody; under a ruleset an unlink needs LANDLOCK_ACCESS_FS_REMOVE_FILE on /tmp, which a socket-only rule would not carry).
- M2 (-env:OSL_SOCKET_PATH=/job/ipc) and M3 (environment variable OSL_SOCKET_PATH=/job/ipc): the bind path is unchanged, still under /tmp; /job/ipc stays empty.
- M4a/M4b (/tmp and /var/tmp not writable): soffice fails with "ERROR: no valid pipe path found." and produces no PDF, with or without the M2 option. The pipe directory is chosen from /tmp then /var/tmp only; nothing under the job directory or TMPDIR is considered. So the bind cannot be moved into the job directory, and with an unwritable /tmp the engine cannot run at all.
- M5 (--nolockcheck): bind path unchanged (re-confirms research Pitfall 1).
- M6 (soffice.bin directly, bypassing the wrapper and oosplash): still binds under /tmp, exit 81, no PDF (the wrapper's environment is needed).
- M7: soffice's exec set is {/bin/sh (dash), basename, dirname, grep, sed, uname, /usr/bin/soffice -> /usr/lib/libreoffice/program/soffice, oosplash, soffice.bin}; verapdf's is {/opt/verapdf/verapdf, dirname, uname, which (-> which.debianutils), /usr/bin/java -> /usr/lib/jvm/java-17-openjdk-arm64/bin/java}.
