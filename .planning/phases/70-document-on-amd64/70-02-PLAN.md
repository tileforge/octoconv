Planner findings built into this plan:
- The measurement has to go through the PRODUCTION wire format (`<worker> __sandbox-exec ... --
  <engine>`), not only through scripts/cmd/sandbox-probe, because the socket right is new in that
  wire format. cmd/document-worker has no helper mode yet; this plan adds exactly that first
  statement and nothing else of 70-03's startup sequence.
- scripts/sandbox-paths-measure.sh's verify phase judges sufficiency by exit status. SANDBOX-PATHS.md
  "Ловушки" §8 records why that is not enough (ghostscript's same-size skeleton), and 70-RESEARCH.md
  shows veraPDF exits 7 on both a denial and a verdict. So document gets a content-judging driver.
- veraPDF runs a JVM. A missing cgroup or /proc read does not fail a small validation; it silently
  changes heap and CPU sizing inside the 1 GiB container. Removal alone would drop those reads, so
  they are judged by `java -XshowSettings:system` equality instead.
- The job directory is mounted at /tmp/job, beneath /tmp as in production (the worker creates job
  directories under os.TempDir()), so a socket or read-write rule on /tmp is measured in the layout
  it will run in.

Output: the socket right (per the decision), the measured and narrowed soffice and veraPDF sets
with conf05 blocks, the /tmp route, and the measurements 70-03's preflight depends on.
