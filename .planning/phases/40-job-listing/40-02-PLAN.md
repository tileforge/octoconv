| client → GET /v1/jobs | untrusted ?status/?engine/?limit/?cursor query params cross here; auth.Middleware has already resolved the trusted client.ID |
| handler → Repo.List | only the trusted client.ID + validated/bound filter+cursor+clamped-limit are passed down |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-04 | Information Disclosure | handleListJobs scoping | mitigate | The caller's `client.ID` from auth.ClientFromContext is the sole client scope passed to Repo.List — no client-supplied id is ever honored; TestListJobs_ScopedToCaller asserts it, and Plan 01's DB leak test proves the SQL enforces it (404-not-403 ownership model, mirrored at the SQL layer) |
| T-40-05 | Tampering | ?cursor | mitigate | Decoded via jobs.DecodeCursor; any malformed/tampered value → 400 before DB work, never a panic or SQL-injection vector (values reach Repo.List as bound params only) |
| T-40-06 | Denial of Service | ?limit unbounded page | mitigate | Server-enforced clamp to `[1, JobsListMaxPageSize]` (default 100, D-06); above-MAX clamps (not rejects); TestListJobs_LimitClampedToMax proves it |
| T-40-07 | Tampering (filter injection) | ?status/?engine | mitigate | Fail-closed 422 validation against the known status set + registry-derived engine classes BEFORE any query; values then travel as bound `$N` params in Plan 01 — never string-interpolated |
| T-40-SC | Tampering | dependencies | accept | No new packages — stdlib (net/http, strconv) + existing chi/convert/jobs/auth only (REQUIREMENTS.md: zero new Go deps). No install task, no legitimacy gate |
