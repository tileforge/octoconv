<objective>
Complete the OCR foundation with the streaming PDF path and page-granular progress (OCR-02, OCR-04): `pdfinfo`→page-count cap→born-digital check FIRST, then a per-page loop (per-page page-box bound → `pdftoppm -f N -l N -r 300` → tesseract → DELETE the page image before the next iteration) — never rasterizing the whole PDF. Implement `ProgressConverter.ConvertWithProgress` driving a page-based estimator (`pages_done/total_pages`, ETA from seconds/page) via `sink.Update`; a single-image job reports null→100 with zero ramp. A NEW page-based estimator lives in its own file and does NOT touch progress.go's ffmpeg-specific parser.

Purpose: Closes the load-bearing memory-safety criterion (SC2 — streaming, never whole-PDF render, Pitfall 1) and makes OCR the second `ProgressConverter` implementor with zero changes to the v1.9 progress/SSE/webhook machinery. The multi-page merge is proven valid-XML on adversarial input (Pitfall 5, the highest-risk failure mode for the pdf→hocr / pdf→alto pairs).
Output: `internal/convert/ocrpdf.go`, `internal/convert/ocrprogress.go` + tests.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client PDF bytes → poppler pdftoppm | untrusted PDF rasterized page-by-page (CVE surface) |
| rendered page image → tesseract/leptonica | untrusted decoded raster into the OCR engine |
| OCR'd text → merged multi-page hOCR/ALTO | untrusted recognized text assembled into one structured XML document |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01 | Denial of Service | multi-page PDF memory bomb | mitigate | enforceMaxPages BEFORE the loop; per-page `-f N -l N` render with os.Remove of each page image before the next — bounded to one page in flight, never whole-PDF rasterize (SC2) |
| T-43-01b | Denial of Service | single degenerate page-box → 300 DPI rasterize | mitigate | enforcePageBoxBound (Plan 02) called per page BEFORE pdftoppm — rejects ErrOCRPageBoxTooLarge fail-closed, bounding the physical-size axis the page-COUNT cap misses |
| T-43-05m | Injection | merged multi-page hOCR/ALTO with `&`/`<`/`>` | mitigate | per-page fragments assembled via the Plan 03 ocrPageMerger (encoding/xml, never string concat); hermetic TestOCRMergePagesRoundTrip proves the MERGED document parses valid XML on adversarial content (Pitfall 5) |
| T-43-06 | Denial of Service / abuse | born-digital PDF re-OCR | mitigate | detectBornDigitalPDF gate fires before any render |
| T-43-04c | Tampering | pdftoppm + tesseract on malformed input | mitigate | both run through hardened runCommand (Setpgid + SIGKILL-on-timeout) per page; server-owned temp dir removed on every return path |
| T-43-07 | Denial of Service | per-page disk accumulation | mitigate | each page image deleted before the next iteration; temp dir cleaned unconditionally |

No package-manager installs in this plan (zero new Go dependencies) — package legitimacy gate N/A.
