<objective>
Make the daily byte and job-count caps real in the one operator configuration
where they currently do nothing: daily limits set with no concurrency cap.

Purpose: `evaluate()` compares a request against `client_usage_daily`, a rollup
written only at the terminal transition, so admitted-but-unfinished work is
invisible to it. When `max_concurrent` is NULL there is nothing else bounding
how much of that work can pile up, and the cap rejects nothing until a job
finishes. The verifier reproduced this live: `max_daily_jobs = 2`,
`max_concurrent = nil`, 50 sequential `Repo.Create` calls, 50/50 admitted. This
plan closes that by charging in-flight (`queued` + `active`) work into the daily
comparison inside the advisory-locked transaction that already exists, and by
deleting the in-code claim of a bound that never held.

Output: an in-flight-aware daily evaluation, a corrected comment, a dated D-15
amendment, and the daily-only test coverage that the current matrix
structurally cannot provide.
</objective>
