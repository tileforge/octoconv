## Task 1 — the durable system has to accept a ninth engine first

**`jobs.engine` carries a CHECK constraint, and every engine class this project
has added needed its own migration to widen it** — `0005_html_engine.sql`,
`0006_audio_engine.sql`, `0009_ocr_engine.sql`, `0010_pandoc_engine.sql`, each
dropping `jobs_engine_check` and re-adding it with one more value.

Add `0016_tectonic_engine.sql` following those four exactly, including their
comment explaining that `jobs_engine_check` is Postgres's auto-generated name
and is therefore what must be dropped.

Without this, `repo.Create` fails on a constraint violation for **every** tex
job. Nothing else in this plan would work, and the failure would surface at the
first end-to-end run as a database error with no obvious connection to the
engine class being new.

`client_limits.engine` and `client_usage_daily.engine` deliberately carry **no**
allowlist (both migrations say so in as many words), so they need no change —
stated here so a reader does not go looking for a second migration.

**`convert.AllEngines()` also grows**, and its doc comment says "the eight
engine classes" in prose that must become nine.
`TestAllEnginesCoversEveryEngineClass` enforces the const block and the slice
agree, so a missed entry fails loudly — but the prose is not covered by that
test and has to be corrected by hand.

**Verify:** `go run ./cmd/migrate` against live Postgres, then insert a job row
with `engine='tectonic'` and confirm it is accepted. **Inversion:** insert
`engine='nonsense'` and confirm it is still rejected — a migration that widens
the constraint to everything would pass the first check and destroy the point of
having it.

## Task 2 — queue and dispatch

- `queue.QueueTectonic` / `queue.TypeTectonicConvert`, byte-identical to
  `convert.EngineTectonic` by construction (the invariant `EngineDescriptor.Engine`
  documents and relies on).
- `Client.EnqueueTectonicConvert`, with `tectonicUniqueTTL` derived from
  `TECTONIC_ENGINE_TIMEOUT` the same way every other engine's is.
- The engine dispatch in `handleCreateJob`.

**IN-02 applies from the first commit.** The timeout env var must be read
identically by every `queue.NewClient()`-constructing service, because the
unique-TTL derivation happens in each enqueuing process. A mismatch does not
error — it silently produces duplicate processing.

**Verify:** the existing per-engine dispatch test grows a tex row rather than
gaining a bespoke test of its own.

## Task 3 — the descriptor and its classification, argued not copied

`TectonicDescriptor` with `IsTerminal: isTectonicTerminal` and
`FailureCode: tectonicFailureCode` (64-03 fills in the unsupported-package
branch; this plan establishes the rest).

**Argue the polarity branch by branch, in the descriptor's doc comment.** Phase
56's descriptors show polarity genuinely disagrees between neighbours —
`isAudioTerminal` treats an ffmpeg-stage timeout as terminal and a whisper-stage
timeout as transient, `isAVTerminal` has the opposite shape. Copying a
neighbour's classification is the same antipattern as copying its timeout:

- **LaTeX compilation error** (undefined control sequence, unbalanced braces) —
  TERMINAL. Deterministic on the document; a retry reproduces it exactly.
- **Engine timeout** — TRANSIENT. A multi-pass document under load is the one
  failure here that depends on something other than the input. Same polarity as
  OCR and probe, arrived at independently and for the stated reason.
- **Non-convergence** (tectonic gives up rerunning) — decide and state which.
  It is a property of the document, so the argument points terminal; say so
  explicitly rather than letting it fall through to the shared classifier.
- **Options present** — TERMINAL. This engine takes none this phase; a populated
  `Opts` map is a corrupt column value, which D-10 already classifies terminal
  for every engine.

**Verify:** rows in `internal/worker/pinning_test.go` for the terminal default
and the transient default, following the existing eight.

**Verify:** the plumbing test above; plus `go build ./cmd/tectonic-worker`.

## Task 5 — the API must publish this engine's ceiling

`cmd/api/main.go`'s `EngineTimeouts` map gains
`convert.EngineTectonic: envDuration("TECTONIC_ENGINE_TIMEOUT", <default>)`, and
`internal/api/api.go`'s `defaultEngineTimeouts` gains the same key.

**This is a named must-have because it has already been shipped wrong once.**
`NewServer`'s default map applies only when `EngineTimeouts` is nil, and
`cmd/api` supplies a non-nil map — so omitting the key made the real API publish
sanitize offers with `estimated_max_seconds: 0` while the worker used its own
value. Caught in review on PR #12, not by a test.

**Verify:** a test asserting the tex engine's published
`estimated_max_seconds` is non-zero, so the PR #12 defect cannot recur silently.

## Task 7 — end to end, on live infrastructure

Upload a real `.tex` through `POST /v1/jobs` with `target=pdf`, let
`cmd/tectonic-worker` consume it, and fetch the result. Assert the output is a
PDF and that it contains what the document asked for — **formulas,
cross-references and a bibliography** (TEX-01 asks for typography, not for a
file with the right magic bytes).

The bibliography uses `biblatex` with `backend=bibtex` (D-07: no biber binary in
the image). If the document does not resolve its citations, that is a finding
about D-07's stated cost and must be reported as such, not worked around by
installing biber — that decision has a security argument behind it and reversing
it is a Rule 4 deviation.

**Gates:** `gofmt`, `go vet`, `go build`, `go test ./... -count=1` against live
Postgres + Redis + MinIO, `scripts/ci-helm-checks.sh`, `yq` over
`docs/openapi.yaml` and `docker-compose.yml`, and the helm before/after diff.
Serially, never alongside a Kubernetes run.
