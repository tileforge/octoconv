against the reduced bundle (sha256 f42d5eed...02ff).

THE OBVIOUS INVERSION PROVES NOTHING, AND THAT IS WHY THERE ARE THREE ROWS

The plan says: prove --untrusted refuses the hostile document, then invert by
removing --untrusted. Removing it changes nothing, because shell-escape is OFF
BY DEFAULT -- the document fails either way and the comparison is meaningless.
What --untrusted actually guarantees is that shell-escape cannot be enabled
REGARDLESS of other flags, so the inversion has to try to enable it.

  configuration                          exit   sentinel
  --untrusted (the production argv)        0     absent
  --untrusted AND -Z shell-escape          0     absent    <- the guarantee
  -Z shell-escape, no --untrusted          0     PRESENT   <- the fixture works

The third row is what makes the second worth anything.

TWO WAYS THE FIRST FIXTURE PROVED NOTHING, BOTH FOUND BY RUNNING IT

1. A RELATIVE sentinel path. All three configurations reported "no sentinel",
   including the permissive one -- and the engine log said
   `note: running shell command: touch SENTINEL_WRITE18`. It HAD run; tectonic
   executes shell commands in its own working directory, so the file was
   created somewhere the test never looked. The fixture now uses an absolute
   path.

2. BOTH VECTORS IN ONE DOCUMENT. The \input{|"cmd"} line raised a hard error
   that aborted the run before \write18's effect could be observed. One vector
   per document.

WHAT TEX-04 NAMES THAT TECTONIC DOES NOT IMPLEMENT

  warning: piped inputs from external commands are not implemented in Tectonic
  error: ! LaTeX Error: File `|touch ....tex' not found.

\input{|"command"} cannot work in tectonic at all. There is no fixture for it
because there is nothing to prove: the vector is absent from the implementation,
not blocked by our configuration. Recorded rather than quietly satisfied by a
test that would have passed for a reason unrelated to anything this project
does.
