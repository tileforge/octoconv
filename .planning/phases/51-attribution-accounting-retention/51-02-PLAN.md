<objective>
Make every terminal job transition write its consumption into `client_usage_daily` inside the transition's own transaction, so the accounting is exactly-once by construction rather than by a separate idempotency mechanism (ACCT-02, ACCT-03).

Purpose: This is the correctness core of Phase 51. Everything downstream in v1.12 — quota enforcement (52) and operator visibility (53) — reads these numbers, and a usage row lost to a worker crash between a committed `MarkDone` and an adjacent accounting write is unrecoverable, because neither an asynq retry nor the reconciler revisits a terminal job.
Output: A transactional rollup write, the widened `MarkDone`/`MarkFailed` signatures, and tests that prove the sums and the exactly-once property against a live Postgres.
</objective>

<design_decisions>
Two decisions are made here explicitly, because CONTEXT.md flags both as open and an executor who guesses will get them wrong.

**1. Transaction scoping (resolves D-03's 2026-08-02 correction).**
`Repo.Inputs`/`Repo.Outputs` are pool-scoped (`repo.go:421,448`) and MUST NOT be called from inside `transition`'s `apply` closure — that would read outside the transaction and defeat the exactly-once property this plan exists to establish. No `tx`-scoped variants of those methods are added either: materializing two `[]Input`/`[]Output` slices in Go only to sum one column is wasted work. Instead the rollup is ONE `tx.Exec` statement whose byte totals are correlated `sum(size_bytes)` subqueries. This satisfies the SEED-017 constraint (sum over all ordinals, never ordinal 0) more strictly than the slice form, since there is no ordinal in the statement at all.

**2. Where client_id / engine / wall-time come from (refines D-03a).**
D-03a is honored for wall-time: `MarkDone` and `MarkFailed` gain an `attempt time.Duration` parameter threaded from the call sites, because per-attempt engine time is the one value Postgres cannot know.
D-03a is deliberately NOT followed for `client_id` and `engine`. Those are read inside the statement from the `jobs` row that `transition` has already locked `FOR UPDATE`. Reason, discovered while mapping the blast radius: `MarkFailed` is also called by the reconciler's exhaustion path (`internal/reconciler/reconciler.go:270`), which has a `jobs.StaleJob{ID,Status,Engine}` and no `client_id` at all. ROADMAP SC2 requires reconciler-recovered jobs to be accounted, so threading `client_id` from every caller would force either a widened `FindStale` or a second query in the reconciler — more blast radius for a value the locked row already holds authoritatively. Record this refinement in the SUMMARY.
</design_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker/reconciler process → jobs repository | A crashing or retrying process drives terminal transitions; correctness cannot depend on the process surviving |
| job artifact rows → durable accounting | `job_inputs`/`job_outputs` byte sizes become the numbers a future quota enforces against |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-05 | Repudiation | usage under-reporting via a crash between status commit and accounting | mitigate | Rollup executes on the transition's own `pgx.Tx`; a failed rollup aborts the status change instead of losing the usage (D-05), proven by Task 3's outside-the-closure inversion check |
| T-51-06 | Tampering | double-counting via reconciler re-processing or asynq retry | mitigate | `transition`'s `SELECT ... FOR UPDATE` + source-status allow-list makes a second terminal commit impossible; asserted on the usage TOTAL, not on the error, by `TestRecordUsageExactlyOnceUnderConcurrentMarkDone` |
| T-51-07 | Denial of Service | a client deleted mid-flight wedging jobs in `active` | mitigate | `WHERE j.client_id IS NOT NULL` in the rollup select: an orphaned job still reaches its terminal state and simply records no usage (tested) |
| T-51-08 | Information disclosure | SQL injection via status/engine values | mitigate | Every value is a bound `$N` parameter or a Go constant; no string concatenation in the statement |
| T-51-SC | Tampering | dependency supply chain | mitigate | No packages installed; `git diff go.mod go.sum` empty is an acceptance criterion |
</threat_model>
