Output: A compiling, fully wired tree and a race test that fails if the rollup ever leaves the transition transaction.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| asynq task → worker handler | A retried or duplicated task re-enters a handler for a job that may already be terminal |
| reconciler sweep → jobs repository | A background sweeper mutates jobs a live worker believes it still owns |
| job row → Prometheus label | `job.ClientID` becomes a metric label value at 14 call sites |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-09 | Tampering | double-counted usage after a stale recovery | mitigate | Guarded transition rejects the zombie worker's terminal write; asserted on the usage total by `TestSoakStaleRecoveryCountsUsageExactlyOnce` |
| T-51-10 | Repudiation | reconciler-exhausted jobs invisible per client | mitigate | Exhaustion branch now records both the Postgres rollup (via MarkFailed) and the per-client counter; covered by `TestSoakExhaustedJobIsAccounted` |
| T-51-01 | Denial of Service | cardinality via `job.ClientID.String()` at 14 sites | mitigate | Every call routes through `metrics.RecordClientJobOutcome`, which resolves the id through the Plan 01 ceiling allocator; the all-zero UUID of an orphaned job collapses to `overflow` |
| T-51-11 | Denial of Service | a metrics call panicking inside a handler | accept | `RecordClientJobOutcome` performs a map lookup and a counter increment with no I/O and no error return; it sits on the same fire-and-forget path as the existing `RecordJobOutcome` |
