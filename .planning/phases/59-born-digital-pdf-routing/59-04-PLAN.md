Передать `targetFormat` в `ocrPDFGuardStage` и развести два исхода ВНУТРИ него — не рядом с ним и не до него. Доккоммент функции про «единственную точку решения для обоих входов» обязан остаться истинным: `convertPDF` вызывается обоими входами, значит и таргет-зависимость они получают одну.

Новая форма гарда возвращает достаточно, чтобы вызывающий понял, закончена ли работа: число страниц (как сегодня) плюс извлечённые байты и признак «результат уже получен». Конкретная сигнатура — на усмотрение исполнителя; требование одно: `convertPDF` не должен воспроизводить у себя решение о таргете, иначе точек решения снова становится две.

Три исхода:

  - `targetFormat == "txt"` и непробельных символов больше порога → извлечённые байты и есть результат конверсии. `convertPDF` пишет их в `outPath` и вызывает `validateOCROutput` — тот же путь завершения, что у OCR-результата, без специального случая. Ни одного рендера, ни одного вызова tesseract.
  - `targetFormat == "txt"` и символов не больше порога → это скан. Обычный per-page цикл OCR, как сегодня.
  - `targetFormat` — `hocr` или `alto` → `pdftotext` НЕ вызывается вообще, сразу per-page цикл. Клиент просит боксы, `pdftotext` их не производит, значит вызов ничего не решает и тратить процесс на него незачем. Это наблюдаемое свойство, и оно проверяется в Task 3 подсчётом вызовов.

**Пределы не ослабляются.** Проверка числа страниц (`ocrPDFPageCount` + `enforceMaxPages`) остаётся ПЕРВОЙ и выполняется для всех трёх исходов, включая извлечение. Документ на десять тысяч страниц отвергается по числу страниц независимо от того, есть ли у него текстовый слой: это ограничение на размер работы, а не на способ её выполнения.

**Прогресс.** На пути извлечения per-page цикла нет, поэтому `onPage` не вызывается ни разу, и `ConvertWithProgress` не эмитит ни одного `sink.Update`. Это законно и уже описано в контракте `ConvertWithProgress` для image-пути («emits ZERO sink.Update calls... the worker maps a converter that reports nothing to null->100»). Записать это в доккоммент явно — второй случай нулевого прогресса не должен выглядеть недосмотром.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| недоверенный PDF → `pdftotext` в воркере | Внешний парсер C++ на клиентских байтах; уже существующая граница, план её не расширяет |
| результат `pdftotext` → выход джобы | НОВОЕ: байты, произведённые парсером из недоверенного входа, становятся артефактом, отдаваемым клиенту |
| воркер ↔ клиент | Изменение исхода джобы с failed на done — наблюдаемое изменение контракта |
