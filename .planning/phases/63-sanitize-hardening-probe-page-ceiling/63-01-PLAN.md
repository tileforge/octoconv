## Task 1 — pin the three inputs before fixing anything

Extend `scripts/sanitize-corpus.py` with three fixtures, and add each to the
corpus manifest so D-15 pinning applies (`git rev-list --count HEAD -- <file>`
must stay 1 after this phase).

1. **`icc_multichunk.jpg`** — a valid ICC profile split across three APP2
   chunks, where chunk 2's first four data bytes are `00 00 00 04`. That is the
   exact input today's `declared` read rejects. The generator must assert the
   split is well-formed (`count` equal in all three, sequences 1,2,3) so a
   broken generator cannot masquerade as a passing fix — the phase-60 lesson
   that a grep-only self-check cannot see a malformed fixture.
2. **`endstream_in_stream.pdf`** — a PDF with one binary stream whose payload
   contains `endstream`, and (separately) `startxref` and `%%EOF`. Built with a
   correct `/Length` so the file is genuinely valid; the point is that the
   substring scan disagrees with the dictionary.
3. **`ooxml_rel_targets_main.docx`** — a docx whose `.rels` carries a
   relationship whose `Target` is `document.xml` itself with a type that
   `relationshipDrivenDrops` drops.

Run each fixture through the CURRENT code and record what happens. Do not skip
this: the failure transcript before the fix is what makes the after-transcript
mean something, and two of these three are believed-broken rather than
observed-broken.

**Verify:** each fixture reproduces its finding, and `check_jpeg_structure` /
`check_pdf_structure` pass on the new files.

## Task 2 — ICC: assemble, then decide (SANI-07)

Replace the per-chunk `declared` read with a chunk-set pass.

- Collect APP2 segments carrying `ICC_PROFILE\0` into `iccChunkSet` entries of
  `(sequence, count, payload)`.
- Valid when: `count >= 1`; every chunk agrees on `count`; `1 <= sequence <= count`;
  no repeated sequence; every sequence in `1..count` present; assembled length
  within `iccMaxProfileBytes`; and `count <= iccMaxChunks`.
- Valid → every chunk emitted verbatim, in file order. Invalid → all dropped.
- `iccMaxProfileBytes` comes from the ICC spec's own maximum, cited in a comment
  by section number. `iccMaxChunks` is 255 — the field is one byte, so anything
  larger is unrepresentable, not a policy choice.

The walker in `sanitizeJPEG` becomes two passes over the segment list. Keep the
existing fill-byte and entropy-coded-data handling exactly as it is; this task
changes which APP2 segments are written, nothing else about the walk.

**Verify:** `icc_multichunk.jpg` round-trips byte-identical in its APP2 segments.
Inversion: drop the sequence-completeness check → the gap fixture is kept
partially, and the test that asserts whole-set-or-nothing fails. Record the
output.

## Task 3 — PDF stream ranges from `/Length` (SANI-08)

First **measure**, then write.

- Across the pinned corpus, run today's Ghostscript output through a throwaway
  probe that reports, per stream: direct `/Length` or indirect, and whether the
  `/Length` end and the `endstream` end agree. Record the counts in the summary.
  This tells us whether the indirect path is exercised by real output or only by
  a hand-built fixture, and the answer belongs in the record either way.

Then, in both `pdfStreamRanges` and `pdfNonStreamBytes` (still two functions,
D-02 in CONTEXT):

- Scan backwards from the `stream` keyword to the opening `<<` of its dictionary
  and read `/Length`.
- Direct integer → end is `start + Length`, **confirmed** by `endstream`
  appearing after at most a short run of whitespace. Disagreement is malformed
  input (`ErrSanitizeMalformedInput` on the sanitizer side,
  `ErrSanitizeUnverifiable` on the verifier side — the verifier never claims a
  file is malformed, it claims it cannot verify it).
- Indirect `/Length N G R` → resolve from a first pass indexing `N G obj`
  offsets, reading the integer that follows. Unresolvable → fail closed, no
  substring fallback.

Extend `TestStreamRangesAgreeWithTheVerifier` with `endstream_in_stream.pdf`,
and add a direct assertion that the redactor's protected range covers the whole
payload of that stream.

**Verify:** the redaction leaves the stream bytes untouched, and
`verifySingleRevision` reports one revision for a file whose stream contains
`startxref`/`%%EOF`. Inversion: restore the substring end in one of the two
walkers → the agreement test names which walker diverged. Record the output.

## Task 4 — the verifier requires the document (SANI-09)

- Add `ooxmlMainPart(format) string` — the closed map from format to required
  part, in the same shape as the other closed vocabularies in this package.
- `verifyOOXML` takes the format, requires that part to be present in the
  listing, and requires `[Content_Types].xml` to carry an `Override` (or a
  `Default` covering its extension) naming a content type for it. Missing
  either → `ErrSanitizeUnverifiable`, naming which of the two is absent.
- Thread the format from the single call site.

**Verify:** `ooxml_rel_targets_main.docx` is rejected rather than delivered.

the test that covers that case fails. Both halves must be separately load-bearing;
if removing one does not fail anything, it is decoration and must be deleted
rather than kept.
