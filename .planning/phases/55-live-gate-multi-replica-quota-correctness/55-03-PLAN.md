A daily quota rejection can currently advertise `Retry-After: ~86400` for a quota that has already reset, because `quotaRejection` calls `secondsUntilUTCMidnight(time.Now())` on the API process's own wall clock, independent of when the Postgres transaction evaluated `(now() AT TIME ZONE 'utc')::date`.

Purpose: this is an error-contract change across a package boundary, which is exactly why it was deliberately deferred out of PR #5 rather than patched in place. It has zero relationship to the live gate and lands in its own plan so the gate's diff stays reviewable (CONTEXT D-07).
Output: a typed daily-quota error carrying the DB-evaluated instant, a handler that reads it, and a straddle regression test.
</objective>
