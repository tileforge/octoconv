<facts_verified_during_planning>
- `POST /v1/jobs` success is **202 Accepted** (`internal/api/handlers.go:805`), NOT 201. RESEARCH.md's
  and PATTERNS.md's `201:*` classification examples are wrong; `scripts/keda-gate.sh:353` has the
  correct literal. Classify admits on `202`.
- Quota rejection body: `{"error": "...", "code": "quota_exceeded"}` with a `Retry-After` header,
  status 429 (`internal/api/handlers.go:1007-1010`). Rate-limit rejection body:
  `{"error":"rate limit exceeded","code":"rate_limited"}`, also 429
  (`internal/ratelimit/ratelimit.go:117`).
- chi's `DefaultLogFormatter` emits the request id as the FIRST token in square brackets and only
  when non-empty (`middleware/logger.go:110-113`), and `middleware.RequestID` honors an incoming
  `X-Request-Id` verbatim (`middleware/request_id.go:69-73`). The api container sets no `tty: true`,
  so `kubectl logs` output is uncolored — no ANSI stripping is needed.
- The log line is written from a `defer`, i.e. at request COMPLETION, and carries the numeric status
  after the `from <ip> - ` segment. That status is a usable cross-check against the client-observed
  status but must not replace it.
- Two rejection paths both produce the same 429 + `quota_exceeded` shape: `PreAdmit`
  (`internal/api/handlers.go:430`, before the S3 write) and `Repo.Create`'s authoritative
  `admitLocked` (`internal/api/handlers.go:757`, after the upload). In a burst, `PreAdmit` is
  unlocked so all N typically pass it and `admitLocked` rejects N-K — which is exactly the
  cross-replica race being proven. The gate must NOT try to distinguish the two paths.

    - opens the FIFO on fd 3 (`exec 3<"$BARRIER"`) and blocks on `read -r -u 3 _`;
    - records `send_ts` in epoch milliseconds immediately after the read returns, using `date +%s%3N` if it is supported and otherwise a portable fallback (macOS `date` does not support `%3N`; prefer `python3 -c 'import time;print(int(time.time()*1000))'` guarded by a `command -v python3` preflight assertion added alongside, or `perl -MTime::HiRes -e 'printf("%d",Time::HiRes::time()*1000)'`; whichever is chosen, assert its availability in the preflight step and record the choice in a comment);

    - records `recv_ts` the same way;
    - writes a single tab-separated line `<i>\t<request_id>\t<send_ts>\t<recv_ts>\t<http_status>` to `$WORKDIR/r<round>-req<i>.rec`.

    Comment the one-process-per-request choice as load-bearing, not stylistic: kube-proxy makes its DNAT endpoint choice once per NEW TCP connection, so a single curl process reusing one keep-alive connection for all N requests would pin every request of the round to one pod even with correct ClusterIP reachability (RESEARCH.md Pitfall 2). Do not collapse this into one curl invocation with `--next`.

    After the loop: `sleep 0.3` to let every subshell reach its blocking read, then release with a single `printf 'go\n' > "$BARRIER"`, then `wait`, then `rm -f "$BARRIER"`.

    Add the preflight assertion for the millisecond-timestamp tool to Plan 55-01's STEP 1 preflight block (append, do not restructure it), so a missing `python3`/`perl` fails in the first ten seconds rather than mid-round.

| gate script -> api Service ClusterIP | 100 authenticated multipart uploads cross into the cluster from the operator host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
