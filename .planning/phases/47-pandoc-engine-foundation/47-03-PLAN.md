Build `PandocConverter` — the standalone, UNREGISTERED converter core (PDOC-01, PDOC-02, PDCE-02) — mirroring `OCRConverter`'s (ocr.go) shape: `Pairs()`/`Engine()`/`Convert(ctx, inPath, outPath, opts)`, argv builders isolated as pure functions, a guard stage before the subprocess. `Pairs()` is a curated directional CLOSED allowlist of meaningful markup interconversions across {md, rst, org, latex, html, docx, epub} (D-02) — NOT the full cartesian, excluding identity and nonsensical directions (e.g. epub->latex/org). `Convert` shells to the real `pandoc` via the existing hardened `runCommand`, security-hardened from line one: raw HTML/TeX passthrough disabled (`-f <fmt>-raw_html-raw_tex`, never enabling `+raw_*`), `--no-shell-escape`, no network, `--standalone` for structural targets. Purpose: This is the phase's highest-risk core — the security hardening (raw-passthrough off, --no-shell-escape, no-network) MUST land in this converter loop, not be spread across later phases (STATE.md). Validated directly against the real pandoc 3.10.1 binary before ANY queue/worker/API plumbing (Phase 48), mirroring the OCR Phase 43 / Audio Phase 30 scope fence.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted document content -> pandoc reader | crafted TeX/HTML markup crosses into an external interpreter that can, by default, execute shell commands / read local files / fetch network resources |
| converter output -> downstream consumers | a bare-fragment or corrupt output must not be accepted as a complete document |
| local pandoc binary provenance | the pandoc binary itself is a supply-chain dependency |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-01 | Tampering / Elevation | pandocConvertArgs -> pandoc reader | mitigate | Raw HTML/TeX passthrough disabled (`-f <fmt>-raw_html-raw_tex`, never `+raw_*`) + `--no-shell-escape` + runCommand spawns no shell (Setpgid/SIGKILL). Proven by the Task 3 `\write18` shell-escape and `\input{/etc/passwd}` canaries (observable non-effect). BLOCK-ON-HIGH: a failing canary blocks the phase. |
| T-47-02 | Information Disclosure | pandoc network/resource fetch | mitigate | Invocation enables no network/remote-resource flag; conversion runs offline. Proven by the Task 3 network-fetch canary (unresolved remote token, bounded by ctx timeout via runCommand's SIGKILL path). |
| T-47-06 | Tampering | Convert output validation | mitigate | Output validated by the same sniffer that guards uploads (LooksLikeHTML/SniffContainer/LooksLikeLaTeX) — a bare fragment or corrupt container fails closed (SC2/PDOC-02). |
| T-47-04b | Denial of Service | Convert input-size guard | mitigate | enforcePandocInputSize fail-closed before the subprocess (Plan 02); runaway expansion bounded by the engine timeout (Phase 49). |
| T-47-SC | Tampering (supply chain) | pandoc binary | transfer | No package install occurs in Phase 47 (tests run against the locally-available pandoc 3.10.1; no go.mod change). Binary provenance is pinned via SHA-256 static-release bake in Phase 49 (D-03). No npm/pip/cargo install in this phase — package-legitimacy gate N/A. |
