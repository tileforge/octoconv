<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ffmpeg subprocess → parser | ffmpeg's `-progress` output is SERVER-generated (trusted), not client input — but a malformed/truncated line must never panic the reader |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-01 | Denial of Service | progress-block parser | mitigate | N/A / non-numeric / truncated lines are guarded (hasData=false) before any strconv — no panic, no unbounded allocation; parser is a bounded per-line consumer |
| T-41-02 | Tampering | percent/ETA math | accept | Input is server-produced ffmpeg output, not client-controlled; clamp to [0,100] bounds any encoder overshoot regardless |
| T-41-03 | Information Disclosure | ProgressUpdate fields | mitigate | Update carries only integers (pct, eta) — no stderr/path text can leak into a client-facing field |
</threat_model>
