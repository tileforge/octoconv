<objective>
Author the SC4 downscale-survival harness for the pandoc class. This is the one script in the phase that is NOT a mechanical clone: pandoc's worst-case job is ~32s (vs ocr's 90-120s), so the ocr "submit LONG, then a SHORT to force a second replica" shape cannot work — the scale-up alone outlives the job. This plan replaces it with a depth-arithmetic shape that puts both replicas mid-job at the moment the HPA decides to scale down, plus a deterministic job<->pod attribution mechanism, and calibrates the fixture offline before anyone touches a cluster.

Purpose: Makes SC4 provable for a fast engine with timestamped, re-runnable evidence.
Output: 1 new script (with an offline `--calibrate-only` mode) + committed calibration evidence. Static checks + a real container-based calibration run in this plan; the live cluster run is Plan 04.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-50-10 | Tampering | a faked or forced downscale invalidating SC4 | mitigate | the script contains no `kubectl scale` and no pod deletion; the 2->1 step is produced solely by the queue-depth metric reaching 2 with threshold 2, and the verify greps for the absence of `kubectl scale` |

| T-50-12 | Tampering (data loss) | premature SIGKILL of an in-flight conversion | mitigate | this is the threat SC4 tests: grace 85 (65s engine timeout + 10s asynq ShutdownTimeout + 10s SIGKILL margin) asserted live on the victim pod, plus exitCode 0 / reason Completed and a strict Killing-before-finished_at ordering |
| T-50-13 | Denial of Service | orphaned exec poller / watcher / fixture container after a failed run | mitigate | poller and snapshotLoop each run in their own process group and are killed by the EXIT trap with a belt-and-suspenders pkill; the fixture container is `docker rm -f`'d by the same trap |
