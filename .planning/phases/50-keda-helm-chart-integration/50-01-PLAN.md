## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| KEDA PromQL scaler -> api /metrics | scaler decisions depend on an external metric that can be absent (api unreachable/unscrapeable) |
| KEDA/HPA downscale -> in-flight pandoc job | a genuine N->N-1 downscale can SIGTERM a pod mid-conversion |
| shared ConfigMap -> every queue-client service | a PANDOC_ENGINE_TIMEOUT mismatch across services silently breaks unique-TTL dedup (IN-02) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-50-01 | Denial of Service | scaledobject-pandoc PromQL scaler | mitigate | WR-01 triad VERBATIM (D-02): `ignoreNullValues: "false"` makes a sustained absent PromQL read as scaler ERROR rather than a silent zero, and `fallback {failureThreshold:3, replicas:1}` holds one pandoc replica instead of falsely scaling to zero behind an api outage with a live backlog |
| T-50-02 | Denial of Service | scaleDown stabilization vs 65s worst-case job | mitigate | `scaleDownStabilizationSeconds: null` (D-01) deliberately preserves the k8s 300s HPA default, which exceeds the measured 65s worst-case job by >4x — a genuine downscale never races a live pandoc job in production |
| T-50-03 | Tampering (data loss) | pandoc-worker pod termination vs in-flight job | mitigate | `terminationGracePeriodSeconds: 85` (= 65s engine timeout + 10s asynq ShutdownTimeout margin + 10s SIGKILL margin, D-04b) — a SIGTERM'd pod finishes the in-flight conversion before SIGKILL; live-proven in Plan 04 (SC4) |
| T-50-04 | Tampering | PANDOC_* env drift between services | mitigate | all PANDOC_* keys live in the single shared octoconv-config ConfigMap consumed via `octoconv.commonEnv` envFrom by every service — structurally impossible for two services to disagree (IN-02) |
| T-50-05 | Information Disclosure | secret.yaml literals | accept | no secret.yaml change this plan; WEBHOOK_SIGNING_SECRET/DB creds resolve from values-local.yaml (.Values.secrets.*) — existing T-24-03 control, unchanged |
| T-50-SC | Tampering | package / dependency installs | accept | zero new Go deps, zero package-manager installs this plan (pure Helm YAML + env keys); no [ASSUMED]/[SUS] packages to gate |

No high-severity unmitigated threat -> no blocking checkpoint required in this plan.
