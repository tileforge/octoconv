<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build host -> tesseract/leptonica source | git tags are mutable/force-pushable; a moved tag silently changes every compiled byte |
| build host -> tessdata_fast download | HTTP fetch of trained-data over the network at build time |
| ocr-worker runtime -> untrusted job input | tesseract/pdftoppm shell out to engines on client-supplied images/PDFs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-SC | Tampering | tesseract+leptonica source build, tessdata_fast bake | mitigate | pin both source repos by tag AND assert `git rev-parse HEAD` == peeled commit; SHA-256 `sha256sum -c -` fail-closed on both .traineddata; runtime `tesseract --version` grep assertion catches a mis-linked binary (mirrors Dockerfile.av-worker/audio-worker). No npm/pip/cargo installs in this phase — the package-legitimacy checkpoint is N/A. |
| T-45-01 | Denial of Service | tesseract OpenMP thread use | mitigate | OMP_THREAD_LIMIT pinned to the cgroup CPU quota so tesseract cannot oversubscribe the container's CPU allocation on the host core count. |
| T-45-02 | Elevation of Privilege | runtime container | mitigate | USER nobody (unprivileged), matching every other engine-worker image. |
| T-45-03 | Denial of Service | image cold-start / registry pull | accept | eng+rus-only tessdata_fast keeps the image small (Pitfall 4); scale-from-zero economics are Phase 46's concern. |
</threat_model>
