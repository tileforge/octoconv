# Requirements: OctoConv v1.16 — CAD Engine

**Defined:** 2026-10-02
**Core Value:** Внутренние сервисы компании могут безопасно и надёжно поставить задачу обработки файла и получить результат — без риска для стабильности или безопасности продакшена.

Предыдущий милстоун заморожен в `.planning/milestones/v1.15-REQUIREMENTS.md`.

## Почему этот милстоун

Превью и размеры для CAD сейчас делает PreviewGenerator: Fusion 360 под GUI на
одной Windows-машине, по одному файлу до 60 с, без ответа при ошибке. Оценка
2026-09-23 (Obsidian `architecture/octoconv-cad-preview.md`) показала, что обе
его задачи — превью и размеры — закрываются headless на Linux. Исследование
v1.16 (`.planning/research/SUMMARY.md`) сузило это дальше замером: ядро
геометрии — OCCT через колесо `cadquery-ocp-novtk` (те же числа, что у FreeCAD,
~250 МБ вместо 1.6–1.9 ГиБ), рендер — VTK + OSMesa без X, без `/tmp` и без
сокетов, DXF — ezdxf + `rsvg-convert`.

`'cad'` и `'render'` уже есть в CHECK-перечнях с самых ранних миграций; два
выхода у одной джобы уже умеет `sanitize`.

## v1 Requirements

### Evaluation (EVAL)

- [x] **EVAL-01**: Выбор ядра геометрии, рендерера и 2D-пути DXF записан по замеру на настоящем образе `debian:bookworm-slim` на нативной архитектуре, под Landlock, с оценкой по пиксельному содержимому, а не по коду возврата
- [x] **EVAL-02**: Есть корпус реальных CAD-файлов с записанными лицензиями: STEP-сборки, IGES только из поверхностей, большие ASCII и бинарные STL, DXF с хэтчами, блоками и размерами, legacy 8-bit (cp1251/Latin-1) — на нём строятся снифферы, лимиты и таймаут
- [x] **EVAL-03**: Замерены пиковая RSS и время на корпусе при `--cpus=2`, размер образа и cold pull; лимиты входа выведены из замера, а не скопированы у PreviewGenerator (40 МБ / 5 МБ / 60 с, порог 500 Б)
- [x] **EVAL-04**: Лицензии библиотек, которые несёт колесо OCP (`libfreeimage`, `libraw`, `libjasper`), проверены для внутреннего использования, решение записано

### Input validation (CADIN)

- [x] **CADIN-01**: `step`/`stp`/`iges`/`igs`/`stl`/`dxf` распознаются по содержимому fail-closed одной и той же логикой при создании джобы и в `POST /v1/inspect`; legacy 8-bit файлы не отвергаются за кодировку
- [x] **CADIN-02**: Обрезанный STEP/IGES/DXF, STL, который проходит и как ASCII, и как бинарный, и бинарный DXF отвергаются 422 с отдельными кодами — расхождение сниффера с настоящим ридером закрыто дифференциальным тестом
- [x] **CADIN-03**: `dwg` распознаётся по сигнатуре и отвергается отдельным кодом «dwg не поддерживается», а не как неизвестный формат
- [x] **CADIN-04**: Вход-бомба (самоссылающийся STEP, гигантское число треугольников, MINSERT, нечисловые координаты) завершает джобу терминальной ошибкой в замеренных границах памяти и времени, а не OOM-киллом воркера

### Render (RNDR)

- [x] **RNDR-01**: Клиент ставит `render` для `step`/`stp`/`iges`/`stl` → `png` и получает непустое изображение детали
- [x] **RNDR-02**: Ракурс — закрытый словарь `iso` (по умолчанию), `front`, `back`, `left`, `right`, `top`, `bottom`; Z вверх, деталь вписана в кадр с полем; неизвестное значение — 422
- [x] **RNDR-03**: Размер изображения — закрытая опция, по умолчанию 1280×1280, с жёстким потолком; вне диапазона — 422
- [x] **RNDR-04**: Опция `quality` (`draft`/`standard`/`fine`) выбирает серверные константы тесселяции относительно диагонали bbox — для рендера и для конверсии в STL
- [x] **RNDR-05**: Фон по умолчанию непрозрачный, `background: transparent` — опцией
- [x] **RNDR-06**: `render` для `dxf` → `png` рисует чертёж сверху; опция ракурса для `dxf` отвергается 422

### Measurements (MEAS)

- [x] **MEAS-01**: Каждая успешная `render`-джоба отдаёт второй выход — JSON с новой ролью `measurements`; PNG остаётся `primary`; клиенту видны оба выхода или джоба падает и не видно ни одного
- [x] **MEAS-02**: JSON содержит точный bbox и число солидов; объём и площадь поверхности считаются только по замкнутым солидам, иначе `null` с закрытым кодом причины — никогда не `0`
- [x] **MEAS-03**: Единицы честно по источнику, с происхождением: STEP/IGES — объявленная в файле, STL — `unspecified`, DXF — по `$INSUNITS` или `unspecified`; для `dxf` только 2D bbox без объёма
- [x] **MEAS-04**: Опция `assume_unit` заполняет только отсутствующую единицу, никогда не переопределяет объявленную, и помечается `source: client_assumed`
- [x] **MEAS-05**: JSON версионирован (`schema`), закрытые словари (единицы, коды причин) задокументированы и сверены с кодом тестом

### Conversions (CCONV)

- [x] **CCONV-01**: `step`/`iges` → `stl`: один бинарный STL в миллиметрах
- [x] **CCONV-02**: `dxf` → `svg`: вектор, model space, видимые слои, текст не теряется; в SVG нет скриптов, `foreignObject` и внешних ссылок
- [x] **CCONV-03**: `dxf` → `pdf`

### Preview contract (PREV)

- [x] **PREV-01**: Контракт превью (SEED-007) записан и закреплён на CAD — формат, размеры, фон, поведение на непревьюируемом входе; всё, что CAD не заставил решить, явно помечено «не зафиксировано»

### Worker (CADW)

- [x] **CADW-01**: `cmd/cad-worker` со своей очередью, Dockerfile, compose, Helm-чартом и KEDA ScaledObject; `cad` появляется в API только целиком — одним атомарным изменением `AllEngines()`
- [x] **CADW-02**: Каждый этап движка работает под своим замеренным Landlock-ruleset; наборы путей записаны в `SANDBOX-PATHS.md` и удерживаются тестом; воркер без Landlock не стартует; preflight на реальном движке судит по выходу
- [x] **CADW-03**: Ошибки классифицируются transient/terminal по этапам; убийство посреди джобы не оставляет живых процессов и не держит джобу до полного таймаута
- [x] **CADW-04**: `CAD_ENGINE_TIMEOUT` замерен по обеим операциям и спарен с потолком размера входа; оценка времени в inspect помечена как замеренная
- [ ] **CADW-05**: Живой гейт всех классов, включая `cad`, проходит на образах из финального коммита; scale-from-zero `cad` через KEDA доказан; `minReplicaCount` для `cad` выбран осознанно
- [x] **CADW-06**: Клиентская документация: `docs/CAD.md`, коды ошибок, OpenAPI, MCP-описания и таблица форматов фронтенда

### Preview

- **PREVV2-01**: Контракт превью (SEED-007) на остальных классах движков

## Out of Scope

| Feature | Reason |
|---------|--------|
| `dwg` | FreeCAD/OCCT его не читают, `libredwg-tools` нет в bookworm, ODA File Converter упирается в лицензию на распространение — решение коммерческое, не инженерное |
| Надпись с размерами на PNG | Размеры отдаются данными в `measurements`; рисовать их — дело потребителя |
| Замена PreviewGenerator, RabbitMQ-адаптер, интеграция GSH/OMS | Движок доступен через обычный API и webhook; интеграция — работа потребителей |
| Камера, заданная клиентом векторами; листы с несколькими видами | Закрытый словарь ракурсов — то, что можно валидировать и тестировать |
| FreeCAD, f3d, Xvfb в образе | Замерено: OCP даёт те же числа при доле размера, VTK + OSMesa рендерит без X и без `/tmp` |
| `volume: 0` или додуманные `mm` для файлов без единиц | Неверный ноль хуже честного `null`: на объём опирается расценка |
