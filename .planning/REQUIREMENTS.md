# Requirements: OctoConv v1.14 — Typesetting & Debt

**Defined:** 2026-09-02
**Core Value:** Внутренние сервисы компании могут безопасно и надёжно поставить задачу обработки файла и получить результат — без риска для стабильности или безопасности продакшена.

## v1 Requirements

### Typesetting (tectonic, ninth engine class)

- [x] **TEX-01**: Клиент может отправить `.tex` с `target=pdf` и получить свёрстанный PDF — реальная типографика с формулами, ссылками и библиографией, а не HTML-рендер

  > Проверено end-to-end на живой инфраструктуре (64-04): формулы, разрешённые перекрёстные ссылки (включая forward) и библиография `biblatex`/`backend=bibtex` — всё вычитано обратно из PDF через `pdftotext`, а не проверено по magic bytes.
  >
  > **Ограничение, найденное при этом:** API однофайловый, поэтому многофайловый LaTeX-проект (`.tex` + `.bib`, любой `\input`) отправить нельзя — библиография работает только при встраивании через `filecontents`. Колонка `ordinal` в `job_inputs` под это уже есть, кода нет. Вынесено в todo.
- [x] **TEX-02**: Сборка идёт **без сетевого доступа**: в образ вшит offline-бандл TeX-пакетов, запиненный по версии и содержимому, и воркер не имеет egress — документ клиента не может решать, что будет скачано
- [x] **TEX-03**: Набор поддерживаемых LaTeX-пакетов **закрыт и объявлен**, а документ, использующий пакет, который движок **не может разрешить**, получает внятный отказ с указанием пакета — а не молчаливо иную вёрстку и не необъяснимую ошибку движка

  > **Переформулировано в 64-03 по результатам измерения** (как PROBE-01 в 63-02). Исходная формулировка требовала отказывать «вне объявленного набора». Замер на реальном бандле в контейнере: из 23 распространённых пакетов 12 успешно компилируются, не входя в объявленные 18 — включая `fontenc`, `inputenc`, `lmodern`, `textcomp`, `microtype` (все пять — в дефолтном LaTeX-шаблоне pandoc) и `fontenc` из документа, прогнанного end-to-end в 64-04. Гейт по объявленному набору отклонял бы валидные документы, которые сервис верстает корректно, — ровно тот дефект, из-за которого в 63-02 был удалён admission-гейт целиком.
  >
  > Объявленный набор (`convert.TeXPackages`, 18) остаётся **обещанием** — что документировано и протестировано. Допуск (`convert.TeXPackageResolvable`, 608 `.sty` из манифеста бандла) — это **что движок вообще может загрузить**. Цель требования (внятный отказ с именем пакета вместо необъяснимого падения) выполняется в исходном виде; изменился только источник истины для отказа. Решение подтверждено оператором до реализации.
- [x] **TEX-04**: Shell escape (`\write18`, `\input{|cmd}`) невозможен из содержимого документа, и это доказано прогоном на враждебном документе плюс инверсией, а не ссылкой на документацию
- [x] **TEX-05**: `tex` — полноценный девятый engine-класс по отлаженному шаблону: своя очередь, `cmd/tectonic-worker`, свой контейнер, transient/terminal классификация, **ИЗМЕРЕННЫЙ** на корпусе с многопроходными документами таймаут, девятый ScaledObject, оставляющий существующие восемь байт-неизменными

### Sanitize hardening

- [x] **SANI-07**: ICC-профиль, разбитый на несколько APP2-сегментов, сохраняется целиком: проверка размера применяется к собранному профилю и полям sequence/count, а не к каждому чанку по отдельности
- [x] **SANI-08**: Границы потоков PDF определяются по `/Length` из словаря потока, а не по первому вхождению подстроки `endstream` — так что бинарный поток, содержащий эти байты, не обрезает защищённый диапазон ни для редакции, ни для подсчёта ревизий
- [x] **SANI-09**: Санированный OOXML-пакет, у которого relationship нацелен на его собственную главную часть, отвергается, а не отдаётся пустым: верификатор требует наличия ожидаемой главной части и её объявления типа

### Probe input bounds

- [x] **PROBE-01** (ПЕРЕСМОТРЕНО 2026-09-03, решение оператора): Документ, число страниц которого превышает `PROBE_MAX_PAGES`, получает машиночитаемый `too_many_pages`, а не падает по таймауту после десяти минут работы воркера. **Требование «при приёме» снято.** Гейт на admission был построен и удалён после шести кругов ревью: счёт страниц нельзя надёжно вывести из недоверенных байтов в процессе API — дерево страниц PDF это дерево, длинный документ объявляет несколько разных счётов, и читатель, не разрешающий ссылку `/Pages` из каталога, не отличит корневой от поддерева. До этого было найдено семь способов отвергнуть **валидный** документ и три ресурсных дефекта на маршруте без семафора. Цена отказа от гейта — одна запись в S3 и один слот очереди на слишком длинный документ; выигрыш — валидный документ никогда не отвергается догадкой. Свидетельства: `.planning/phases/63-.../evidence/`, PR #15
- [x] **PROBE-02**: Отказ по числу страниц классифицирован **терминально** и не тратит бюджет ретраев — в отличие от таймаута, который остаётся транзиентным, потому что зависит от нагрузки, а не от файла

### Operational debt

- [x] **DEBT-12**: Свежая установка чарта не даёт api-поду крашлупить: контейнер ждёт готовности Postgres вместо `exit(1)` на каждой попытке, и `restartCount` при чистом старте равен нулю
- [x] **DEBT-13**: Полный прогон `go test ./...` на живой базе детерминирован: soak-тест реконсилятора больше не может быть сломан in-flight джобой параллельного пакета
- [x] **DEBT-14**: Отчёт `POST /v1/inspect` не может одновременно утверждать `coverage.complete: true` и `unknown/read_failed` во всех своих проверках — «я прочитал файл полностью» и «я не смог его прочитать» перестают уживаться в одном теле ответа. **Было выполнено ещё до начала милстоуна** — todo оказался устаревшим, см. примечание ниже

## Out of Scope

| Feature | Reason |
|---------|--------|
| Полный бандл TeXLive в образе | ~2.69 GiB на слой — на порядок больше любого воркера во флоте; закрытый набор пакетов и дешевле, и честнее (см. `.planning/research/TECTONIC.md`) |
| Сетевой доступ у tectonic-воркера | Документ клиента решал бы, что скачивается — ровно тот вектор, который `sanitize` вычищает из чужих файлов |
| `md → pdf` в этом милстоуне | Пересекает границу движка; принадлежит SEED-018, а не сюда |
| Архивация 26 quick-каталогов как «работа» | Это завершённая работа с незаархивированными каталогами, а не открытые баги — чистка, не требование |

**DEBT-14 — проверено, а не сделано.** Требование писалось по todo от
2026-08-18, перечислявшему три открытых пункта. Проверка кода и прогон тестов
показали, что работы в нём нет:

* item 1 (`read_failed` не делал отчёт неполным) закрыт фазой 59 —
  `ReasonReadFailed` в `makesReportIncomplete`, и это пиннуто тестом
  `TestBuildReportAllChecksReadFailedIsNotComplete`, который прогоняет ровно
  описанный в todo сценарий;
* item 2 (четыре детектора возвращают голый bool, поэтому сбой чтения
  неотличим от «не этот формат») закрыт рефакторингом `readSniffWindow`:
  чтение делается один раз снаружи и сбой репортится как `read_failed`.
  Расширение четырёх сигнатур до `(bool, error)` там же явно отвергнуто как
  D-12, потому что они разделены с конвертационным путём, которому нужен
  только bool;
* item 3 — биллинг GitHub Actions, не код.

Отмечено выполненным, а не удалено: требование верное, оно просто было
удовлетворено раньше, чем сформулировано. Выдумывать под него работу было бы
хуже.
